**준비**
0. Debug/x64 (SIMUL_MODE) 로 빌드 후 `DatumMeasurement.exe` 실행. Setting 의 `CameraRole` 이 `TopBottom` 인지 확인 — 좌측 트리에 **TOP 과 BOTTOM 두 시퀀스**가 모두 보여야 한다. (Side 만 보이면 CameraRole=Side 이니 TopBottom 으로 바꾸고 재시작.)
   - TOP / BOTTOM 각각에 SHOT 이 최소 1개씩 있는 레시피를 로드한다. 없으면 SHOT 을 하나씩 추가한다.

**Test 1 — 독립 시퀀스 동시 실행 (이번 phase 의 핵심 목표, D-01)**
1. TOP 시퀀스의 SHOT 노드를 선택하고 RUN(`btn_start`) 클릭 → TOP 이 실행되기 시작한다.
2. TOP 이 **아직 도는 동안** BOTTOM 시퀀스의 SHOT 노드를 선택하고 RUN 클릭.
3. **기대:** `Sequence is already running` / `실행할 수 없습니다` 류 에러가 **뜨지 않고** BOTTOM 이 시작된다.
   (수정 전에는 여기서 반드시 에러가 떴다. 이게 이번 phase 가 고치려던 바로 그 증상이다.)
   - TOP 사이클이 너무 빨라 겹치기 어려우면 SHOT 을 여러 개 체크한 일괄검사로 TOP 을 오래 돌린 뒤 2번을 수행한다.

**Test 2 — 자기 자신 재실행은 여전히 차단 + 사유 메시지 (D-03)**
4. TOP 시퀀스 SHOT 을 RUN 한 뒤, **같은 TOP** SHOT 을 실행 중에 다시 RUN 클릭.
5. **기대:** 에러 창이 뜨고 본문이 다음 형태다 —
   `실행할 수 없습니다 — 'TOP' 시퀀스가 아직 Idle 이 아닙니다.` + 둘째 줄 `(자기 자신이거나, 같은 물리 카메라를 공유하는 시퀀스입니다.)`
   → **시퀀스 이름 `TOP` 이 메시지에 실제로 찍혀 있어야 한다.** (수정 전에는 이름 없이 `Sequence is already running.` 이었다.)

**Test 3 — 일괄검사도 동일하게 동작**
6. BOTTOM SHOT 여러 개를 체크하고 일괄검사(`btn_batchRun`) 클릭 → 실행 시작.
7. 실행 중 TOP SHOT 선택 후 단일 RUN → **기대:** 차단되지 않고 TOP 이 시작된다(Test 1 과 동일 논리).
8. 실행 중 같은 BOTTOM SHOT 들로 일괄검사를 다시 클릭 → **기대:** `실행할 수 없습니다 — 'BOTTOM' 시퀀스가 아직 Idle 이 아닙니다.` 메시지(제목 `일괄 검사`).

**Test 4 — 회귀 확인 (아무것도 안 도는 평시)**
9. 모든 시퀀스가 Idle 인 상태에서 TOP SHOT RUN → 정상 실행되고 결과가 평소처럼 표시된다.
10. 모든 시퀀스 Idle 상태에서 일괄검사 → 정상 실행 + 완료 후 `일괄 Export` 버튼 활성화.
11. 좌측 트리에서 노드 선택 후 **Grab / 검사Grab / 조명** 버튼 → 이 3개는 이번 phase 범위 밖(전역 게이트 유지)이므로 **평소와 동일하게** 동작해야 한다. 시퀀스가 도는 중에는 여전히 안 눌리는 게 정상이다.

**Test 5 — POC 패널 무변경 확인 (D-02)**
12. 메인 화면 하단 "POC 자동화 임시 테스트" 패널(콤보 + Z-index 입력 + 트리거 버튼)이 **모양·라벨·동작 모두 그대로**인지 확인하고, 트리거 버튼을 1회 눌러 평소처럼 동작하는지 본다.

**Test 6 — 차단 로그**
13. Test 2 또는 Test 3-8 에서 차단이 발생한 뒤 Trace 로그 파일을 열어 `[RUN-GATE] blocked: target=..., busy=...` 한 줄이 기록됐는지 확인한다.

## SIMUL 에서 검증 불가 — 실HW carry-over

**CO-69-01 (open): 실HW TopBottom 공유 카메라 상호배타 미검증**
- 검증 대상: 실장비(비-SIMUL, `CameraRole=TopBottom`)에서 TOP 실행 중 BOTTOM RUN 이 **차단되어야** 한다.
  근거: `WPF_Example/Device/DeviceHandler.cs:221-247` 의 `sharedMil` 경로가 `Devices["CAM_TOP"]` 와
  `Devices["CAM_BOTTOM"]` 을 같은 `MilCamera` 인스턴스로 등록하고, `MdigGrab` 경로에 lock 이 없다.
- SIMUL 에서 재현 불가 사유: `#if SIMUL_MODE` 분기의 `AddVirtualCamera` 가 역할마다 독립 인스턴스를 만들어
  `ReferenceEquals` 가 항상 false → SIMUL 에서는 구조적으로 "공유 없음"이 정답이다.
- 실장비 확인 절차: 실HW 빌드로 TOP SHOT RUN → 실행 중 BOTTOM SHOT RUN →
  `실행할 수 없습니다 — 'TOP' 시퀀스가 아직 Idle 이 아닙니다.` 가 떠야 PASS.
  Trace 로그에 `[RUN-GATE] blocked: target=BOTTOM, busy=TOP` 이 남았는지도 함께 확인.
- 만약 실장비에서 **차단되지 않으면**: 69-01 의 `TryCollectSequenceCameras` 가 디바이스 이름을 해석하지 못하고
  있는 게 아니라(그 경우는 fail-closed 로 차단됨) 두 시퀀스가 서로 다른 인스턴스를 받고 있다는 뜻 →
  `DeviceHandler.Initialize()` 의 MIL 분기가 기대대로 `sharedMil` 을 타는지 먼저 확인할 것.
