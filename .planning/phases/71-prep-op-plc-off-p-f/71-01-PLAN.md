<objective>
`$PREP` 프로토콜에서 `Op` 필드(1=ON / 0=OFF)를 wire 포맷과 코드에서 **완전히 제거**한다. `$PREP` 는 이제 "이 z_index 에 맞는 조명을 켜라" 단일 의미만 갖는다.

**Purpose:** 소등(OFF)은 PLC 가 명시적으로 요청할 일이 아니다. `ApplyShotLightsInternal`(`InspectionSequence.cs:716`)이 매 호출마다 전 채널을 선언적으로 재적용하므로 z_index 전환 시 안 쓰는 채널은 이미 자동으로 꺼진다. 남은 유일한 OFF 목적("사이클 완전 종료 후 전부 소등", LED 수명/안전)은 비전이 사이클 P/F 확정 시점에 스스로 수행하도록 71-02 로 옮긴다. 따라서 PLC 는 더 이상 OFF 를 보낼 필요가 없고, `Op` 필드는 존재 이유가 사라진다.

**Output:**
- `$PREP:site,z_index@` 2필드 수신 파서 (구 3필드 요청은 3번째 필드를 **읽지 않고 무시** — D-71-01)

<locked_decision id="D-71-01">
## 하위호환 결정 (CONTEXT.md 의 "Claude's Discretion" 항목 — planner 가 확정, 재논의 금지)

**결정: 관대한 파싱(lenient) — 필드 2개 이상이면 성공, 3번째 필드가 와도 코드에서 아예 읽지 않는다.**

즉 `bHasFields = dataList != null && dataList.Length >= 2` 를 **그대로 유지**하고, `dataList[2]` 를 참조하는 코드를 전부 삭제한다. `Length == 3` 을 실패로 만드는 코드는 추가하지 않는다.

**근거 4가지:**
1. **무응답 = 라인 정지.** `VisionRequestPacket.cs:296-297` 에서 파싱 실패는 `return null` 이고, null 패킷은 **응답 자체가 나가지 않는다**. 엄격 거부를 택하면 구 펌웨어 PLC 가 `$PREP_ACK` 를 영원히 기다린다 → 설비 정지. 스스로 만든 DoS 다.
2. **같은 파일의 기존 관례.** `TryParseAlignFields`(`VisionRequestPacket.cs:388`)가 `// dataList[2]=모드(skip)` 로 "받긴 하지만 안 읽음"을 이미 문서화된 관례로 쓰고 있다.
3. **선례 커밋 `fbe05c8`** (`$TEST` 에서 z_index 필드 제거)도 거부가 아니라 무시를 선택했다.
4. **잔여 리스크가 낮다.** 구 클라이언트가 `Op=0`(명시 OFF)을 보내면 이제 "해당 z_index 점등"으로 동작한다. 측정 정확도에는 무영향(측정 직전엔 항상 `$PREP` 가 선행해 조명을 재적용한다). LED 가 사이클 종료까지 켜져 있을 뿐이고, 그 종료 시점에 71-02 의 자동소등이 끈다. → threat model T-71-03 에서 accept.
</locked_decision>
