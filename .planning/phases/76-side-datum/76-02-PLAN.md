<objective>
옵션이 켜진 SIDE Datum 은 화면과 저장 캡처에서 가로선과 가로 에지점만 보이게 한다(D-76-06, SDV-03).
세로 검출선, 세로 에지점, 세로 기준선, 원점 십자의 세로 팔을 그리지 않는다. 옵션 OFF 와 TOP/BOTTOM 은 그리는 내용이 한 픽셀도 달라지지 않는다(SDV-04).

Purpose: 검출하지 않은 선을 그리면(이전 값이 남아 있거나 티칭 위치가 그려지면) 운영자가 오해한다(D-76-06 근거).
`DetectedRefAngle2 = 0.0` 만으로는 막히지 않는다 — `RenderDatumFindResult` 는 각도가 0 이어도 방향 벡터(Sin 0 = 0, Cos 0 = 1)가 유효해 선을 그린다(RESEARCH Pitfall 1).
그래서 76-01 의 `IsHorizontalOnlyActive()` 를 표시 쪽에서 직접 검사한다. 캡처의 2차 축은 센티널이 이미 막지만, 원점 십자의 세로 팔은 캡처 쪽에도 명시적 플래그가 필요하다.

Output: `HalconDisplayService.cs` 두 메서드에 표시 게이트, 캡처 스냅샷 플래그 1개, 스냅샷 빌더 삽입 1곳, 캡처 렌더러 분기 1곳. 기존 줄 삭제 0(git diff -w).

## Flagged assumption A-76-E2 (SDV-03, edge probe 'unclassified' — 미해결로 남김, 자동 해소 금지)
D-76-06 '세로 기준 방향(원점 십자의 세로 팔 포함)' 을 다음 두 가지를 모두 가리키는 것으로 해석해 **둘 다** 숨긴다:
(a) 결과 화면의 전체 길이 세로 기준선(원점을 지나는 큰 십자의 세로 팔), (b) 검출 원점 20px 십자의 세로 팔(화면과 저장 캡처 모두). 사용자 문구 '가로선과 가로 에지점만 보인다' 와 맞는 쪽이다.
**숨기지 않는 것(설정·티칭 기준 표시로 보고 D-76-06 범위 밖으로 해석):** 티칭 원점 표시(마젠타 'Datum Origin' 십자 `RenderDatumRefOriginCross`, 빨강 교점 십자 — RefOrigin 위치),
세로 ROI 검색 사각형(편집 ROI, 결과 화면 주황 보정 박스).
**결과로 생기는 것:** 옵션 ON 에서 검출 원점의 가로 위치는 가로선 위 짧은 가로 표식과 'Find (row, col)' 라벨로만 보인다. 옵션 ON 상태로 티칭하면 세로 검출선(노랑)과 세로 에지점(주황)이
화면에 나오지 않으므로, 티칭 결과의 세로선을 눈으로 확인하려면 옵션을 잠시 끄고 본다(D-76-06 을 우선).
해석이 틀리면 76-03 UAT U-6 에서 사용자가 지적한다 — 모두 표시 전용 게이트라 되돌리기 쉽다(reversible).
