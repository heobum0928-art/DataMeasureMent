# Phase 78 — 리뷰어 NG 원인 분석 (HUMAN UAT)

**상태:** 사용자 확인 대기
**버전:** 1.7.49.0 (2026-09-17, `WPF_Example/VersionDefine.cs`)
**빌드:** **Debug|x64 전용.** Release|x64 는 `OutputPath` 가 `D:\Data\` 라 빌드만 해도 현장 배포 exe(현재 1.7.48.0)를 덮어쓴다 — 이 UAT 절차 전체가 Release 빌드를 요구하지 않는다. 배포(1.7.49.0 을 D:\Data 에 올리는 것)는 이 체크포인트 범위가 아니며, 앱 종료 확인 → 사용자 승인 → 별도 배포 절차로 진행한다.

각 항목에 `PASS` / `FAIL(증상)` / `PENDING` / `대기` 중 하나를 기록한다.

## 실행 환경

- **이 PC(사무실, Debug|x64) 에서 전부 할 수 있는 것:** U-1 ~ U-7 — 이미 저장되어 있는 날짜 폴더(20260601, 20260811, 20260915, 20260916, 20260917 등)의 cycle.json 을 리뷰어로 여는 것만으로 확인한다. 실제 카메라·PLC 가 필요 없다.
- **자동(또는 SIMUL TCP) 사이클이 필요한 것:** U-8 — 새 cycle.json 에 진단 값이 실제로 기록되는지는 자동 사이클을 최소 1회 돌려야 확인할 수 있다. 이번 승인에 포함하면 가장 좋지만, 어렵다면 U-8 은 `대기` 로 남겨도 U-1~U-7 승인은 유효하다.
- **새 리뷰어 화면(패널)이 실제로 어떻게 보이는지, 문구가 비전 초보에게 이해되는지는 사람이 직접 봐야만 안다 — 자동으로 해소되지 않는다(A-78-E1).**
- 이 앱을 자동으로 켜서 클릭해 주는 도구가 없다. 아래 단계는 전부 사람이 화면을 보면서 직접 수행한다.
- 배포(Release|x64 빌드, `D:\Data` 덮어쓰기)는 이 체크포인트 범위 밖이다.

## 공통 준비 (U-1~U-8 시작 전 1회)

1. **빌드:** `WPF_Example/DatumMeasurement.csproj` 를 **Debug|x64** 로 빌드한다(SIMUL_MODE 활성).
   ```
   "/c/Program Files/Microsoft Visual Studio/18/Community/MSBuild/Current/Bin/MSBuild.exe" WPF_Example/DatumMeasurement.csproj -p:Configuration=Debug -p:Platform=x64 -m -nologo -v:minimal -clp:ErrorsOnly
   ```

   Release|x64 는 빌드하지 않는다.
2. **앱 실행 → 결과 리뷰어 열기:** 메뉴에서 결과 리뷰어(ReviewerWindow)를 연다.
3. **"NG 누적 엑셀 저장" 버튼이 만드는 파일:** 설정의 `ResultSavePath`(기본 `D:\Data\Result`) 바로 아래에 `NG_분석_누적.xlsx` 파일 하나를 만든다(시트 이름 `NG 누적`). 시험 후 이 파일을 지워도 된다 — 지우면 다음에 버튼을 누를 때 새로 시작한다. 이 버튼은 그 날짜 폴더의 cycle.json 과 사진 파일은 읽기만 하고 바꾸지 않는다.
4. **U-8 시험 레시피 복사:** U-8 을 수행할 경우, `D:\Data\Recipe\FAI_1` 폴더를 통째로 복사해(예: `D:\Data\Recipe\FAI_1_UAT78`) 시험용으로 쓴다. **운영 레시피(`D:\Data\Recipe\FAI_1\main.ini`) 는 직접 열어 수정하지 않는다.** 앱의 레시피 저장은 이 시험 복사본에만 한다(77-HUMAN-UAT 공통 준비 2번과 동일한 방식).
5. **SIMUL TCP 사이클이 필요하면:** 77-HUMAN-UAT 공통 준비의 `Test/mock_vision_client.py` / `Test/HandlerCommunicationTest.py` 를 그대로 쓴다.

(NGA-07, D-78-08 — 가능하면 이번 승인에 포함)

목적: 자동(또는 SIMUL TCP) 사이클 1회 후 새 cycle.json 에 기준점·Z 후보 진단 값이 실제로 기록되는지, 레시피를 저장해도 운영 main.ini 에 새 키가 생기지 않는지 확인한다.

준비: 공통 준비 4번의 시험 레시피 복사본을 쓴다. 운영 레시피는 수정하지 않는다.

단계:
1. 자동(또는 SIMUL TCP) 사이클을 1회 돌린다.
2. 새로 생긴 `cycle.json` 을 메모장으로 연다.
3. `DatumDiagnostics` 배열이 있고, 각 항목에 `DatumName`, `IsDetected`, `IsDetectedThisTick`, `OriginRow`, `AngleDeg`, `AlignMatchScore` 가 있는가. 패턴(Align) 기준점 Datum 이면 `AlignMatchScore` 가 0 보다 큰가.
4. Z 범위가 켜진 Shot(77 의 `SIDE_SHOT_1_F9` z4~z6 시험 설정을 그대로 쓸 수 있다)이면, 그 Shot 의 `ZRangeStartIndex`/`ZRangeEndIndex` 가 기록되고, 해당 측정마다 `ZCandidateScores` 배열(각 항목 `ZIndex`/`Ok`/`Score`)이 있는가. `Score` 값이 `Algorithm` 로그의 `[ZFocus] 선택` 줄에 찍힌 후보 점수와 같은가.
5. 시험 레시피(복사본)를 저장한 뒤, `D:\Data\Recipe\FAI_1\main.ini`(운영 레시피, 열기만 하고 저장하지 않는다)를 메모장으로 열어 `LastAlignMatch`·`LastZCandidateScores` 문자열을 찾기(Ctrl+F) — 없는가.
6. 이번 사이클의 판정(P/F)·PLC 응답·일자별 CSV 열 구성이 1.7.48.0 때와 같은가(새 열이 추가되지 않았는가).

합격 기준: 3·4·5·6 확인. 어려워서 못 하면 U-8 전체를 `대기` 로 남겨도 U-1~U-7 승인은 유효하다.

## 알려진 한계

1. **A-78-E1:** 원인 3줄(+함께 의심) 문구가 비전 초보에게 읽히는지는 사람 판단이다(U-1 9번) — 자동으로 해소되지 않는다.
2. **A-78-A1:** R5/R6/R9 임계값(0.15·2.0 / 5·3 / 10%)은 2026-09-15~17 SIDE_1 표본으로만 맞췄다. TOP/BOTTOM·다른 제품에서 과다/과소 판정될 수 있다 — U-6 과 운영 중 계속 확인이 필요하다.
3. **A-78-A2:** R5(기준점 흔들림)는 "같은 FAI = 같은 기준선"으로 측정을 묶는다. FAI 하나에 기준선이 여러 개인 레시피는 대부분 걸러지지만 완전히 보장되지는 않는다.
4. **A-78-A3:** 원본 사진은 검사 직후 워커가 비동기로 쓴다. 쓰는 도중(파일 크기 > 0, 미완성)인 파일을 리뷰어가 열면 기존 전역 예외 창이 뜰 수 있다 — 빈도는 낮고, 다시 누르면 정상이다(U-2 5번).
5. **R8(초점 범위 부족)은 범위 끝 쪽만 판정한다** — 범위 시작 쪽은 동점 규칙 기본값을 따르며 별도 경고가 없다.
6. **옛 cycle.json 의 R8 판정은 검사 당시 z 번호로만 한다** — 기록된 Z 후보 점수가 없기 때문이다.
7. **NG 누적 엑셀 저장은 UI 스레드에서 동기 실행된다** — 큰 날짜 폴더(NG 수천 건)는 저장에 수 초 걸릴 수 있다(U-3 5번에서 실측).
8. **10만 행 이상이면 파일 이름을 바꿔 따로 보관하라는 안내가 뜬다** — 새 파일은 다음 저장부터 새로 시작한다.
