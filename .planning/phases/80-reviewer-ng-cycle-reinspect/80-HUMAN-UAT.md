Algorithm 로그에 `[LocalRef] 기준 ROI·에지 설정이 바뀌어 기준점 가로 사진에서 국부 기준선을 다시 구함 — ` 이 찍히는가. 곧바로 두 번째 RUN 을 하면 이번엔 "다시 구함" 로그가 다시 찍히지 않는가(이미 저장된 국부 기준선을 그대로 쓴다).
2. 기준 ROI 를 띠가 없는 평평한 곳으로 옮기고 RUN 한다 — 실제 원인(에지 못 찾음 등) 문구로 전역 전환되는가.

4. 이어서 메인 툴바 "기준 ROI 시험 찾기" 를 누른 뒤 ROI 를 다시 옮기고 RUN 한다 — 이번엔 "국부" + "다시 구함" 로그가 찍히는가(티칭 사진 파일로 기준점을 잡았기 때문).
5. **(c) 두 장짜리 기준점을 Test Find 로 잡은 뒤, 기준점 노드에서 가로 사진을 다른 파일로 Load 하고 RUN** 한다 — "다시 구하지 않음" 로그 + 전역 전환이 나오는가(사진 경로가 바뀌었으므로).
6. PLC 자동 검사 결과가 이 phase 전과 같은가(옵션 켠 측정의 "기준" 이 여전히 국부로 정상 동작하고, "다시 구함"/"다시 구하지 않음" 로그는 0인가 — PLC 경로는 이 재계산과 무관하다).

## 알려진 한계

1. **PLC 자재 진행 도중 불러오기:** 기준점 tick 과 다음 tick 사이에 리뷰어 사진을 불러오면 그 자재는 기준점 캐시가 바뀌어 NG 가 날 수 있다 — 설비 정지 상태에서 불러올 것을 권고한다.
2. **불러온 동안 설정 저장:** 불러온 상태에서 설정 창에서 설정을 저장하면 리뷰어가 켜 둔 `OfflineInspectMode` 가 그대로 파일에 저장될 수 있다(단, 종료 시 원래 값으로 다시 저장되어 복구된다).
3. **로그인 필요:** 로그인하지 않으면 속성창이 숨겨져 파라미터를 고칠 수 없다.
4. **재검사 결과 비교는 범위 밖:** 재검사 결과와 리뷰어 원래 값을 나란히 비교하는 표시는 이번 phase 범위 밖이며(Deferred), 필요하면 다음 phase 로 넘긴다.
5. **JPG 사진 오차:** 저장 사진이 JPG 라 재검사 값이 실제 검사 당시 값과 조금 다를 수 있다(U-7 참고).
