### ② ⚠ 브리핑 정정 — 구독은 `+=` 가 아니라 `=` 를 써야 한다
브리핑은 `OnCalibError += (msg) => {...}` 를 제안했지만, **형제 콜백 2개는 둘 다 `=` 대입**이다(L96, L107).

옛 클로저가 계속 살아남는다. → **`=` 대입으로 맞춘다.** (같은 메서드 L92~93 이 이벤트에 대해
`-=` 후 `+=` 로 중복 구독을 막는 것도 같은 문제의식이다.)

### ⚠ 이 스크립트를 바꾼 이유 (버그 3개를 실측으로 확인했다)

**버그 ①(Quick #2 에서 발견):** `msbuild | grep | head -25 || fallback` 은 파이프라인 종료코드가 `head` 것이라 항상 0 →
폴백이 영원히 실행되지 않는 **죽은 코드**가 된다.

**버그 ②(이번 계획 수립 중 실측 발견 — Quick #2 의 "고친" 형태에도 남아 있었다):**
`((set -o pipefail; msbuild | grep -iE "error|warning CS|Build succeeded" | head -25) || fallback)` 도 틀렸다.
`//v:minimal //nologo` 로 빌드하면 MSBuild 는 **"Build succeeded." 를 출력하지 않는다.** 실제 출력은 이 한 줄뿐이다:
```
  DatumMeasurement -> C:\Info\Project\DataMeasurement\WPF_Example\bin\x64\Debug\DatumMeasurement.exe
```
→ grep 이 아무것도 못 찾아 종료코드 1 → `pipefail` 때문에 파이프라인 실패 → **빌드가 성공했는데도 폴백이 매번 돌고**,
폴백 역시 같은 이유로 아무것도 출력하지 않아 **검사 전체가 무출력**이 된다(성공/실패 구분 불가).
이 레포에서 그대로 돌려 실제로 출력이 완전히 빈 것을 확인했다.

**해결:** 파이프라인 종료코드로 장난치지 말고 **MSBuild 자신의 종료코드(`rc`)** 를 성공 신호로 쓰고,
로그는 파일로 받아 따로 grep 한다. 폴백 조건이 명시적(`rc != 0`)이라 죽은 코드가 될 수 없고,
`BUILD_RC=` 가 항상 찍히므로 무출력 상태가 생기지 않는다.

**버그 ③(plan-checker 실측 발견):** 스크래치 폴백에 `//p:OutputPath="<슬래시 포함 경로>"` 형태(더블슬래시)를 쓰면
Git Bash(MSYS) 가 이걸 UNC 경로로 오인해 `//` 를 그대로 남기고, MSBuild 는 `MSB1001: 알 수 없는 스위치` 로
**항상** 실패한다 — 즉 폴백이 존재하는 유일한 이유(산출물 잠김)인 바로 그 상황에서 탈출구가 없어지고,
`grep`이 이 MSB1001 텍스트를 컴파일 에러로 오독할 위험까지 있다.
**해결:** 대시 스위치(`-p:`)와 백슬래시 Windows 경로로 교체(§E 스크립트에 반영 완료) — plan-checker가 실제로
`rc=0`을 확인했다.

**빌드 판정 자체의 기준도 정정:** "0줄"이 아니라 **`: error` 0줄 + `warning CS` 12줄(baseline)**. §E 상단에 반영.
