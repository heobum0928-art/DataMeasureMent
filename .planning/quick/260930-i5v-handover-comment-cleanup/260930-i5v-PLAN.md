# 인계 대비 주석 정리 (기능 영향 0)

코드 인수인계 전, 주석에 남은 작업기록 흔적(날짜 서명, Phase/Plan 번호, 결정 코드, quick id, .planning/UAT 참조)을 걷어낸다.
주석이 설명하는 "왜"는 남긴다. 실행 코드와 문자열 리터럴은 한 글자도 바꾸지 않는다.

## 안전 원칙

- 내부 저장소의 `.planning/` 과 커밋 기록은 삭제하지 않는다.
- 작업 전 태그 `before-comment-cleanup` 를 남겨 정리 전 주석을 언제든 꺼내볼 수 있게 한다.
- C# 렉서로 실제 주석 토큰만 수정한다(문자열, verbatim, 보간 문자열, 문자 리터럴 안의 `//` 는 대상 아님).
- 정리 전후 빌드 산출물을 ildasm 으로 IL 덤프해 비교한다. 줄 번호 정보만 달라야 하고 IL 본문은 동일해야 한다.
- 빌드 경고 종류는 baseline(CS0618/CS0162 계열)을 넘지 않아야 한다.

## Task 1 — 기준선 확보

- files: (없음, 태그와 스크래치 빌드만)
- action: 태그 생성, 현재 HEAD 를 스크래치 OutDir 로 빌드, IL 덤프 저장
- verify: 빌드 error 0, IL 덤프 파일 생성
- done: 비교 기준 IL 확보

## Task 2 — 주석 정리

- files: `WPF_Example/**/*.cs`
- action: 렉서 기반 스크립트로 주석 안의 작업기록 흔적만 제거. 비게 된 주석은 삭제(주석만 있던 줄은 줄째 삭제).
- verify: 정리 후 빌드 error 0, 경고 종류 baseline 이내, IL 덤프가 기준과 동일(줄 번호 제외), 문자열 리터럴 변경 0
- done: 흔적 카운트가 크게 감소, 동작 무변경 증명

## Task 3 — 인계용 저장소 뽑기 스크립트

- files: `tools/export_handover.sh`
- action: 지정 커밋의 트리를 `.planning/`, `.claude/`, `CLAUDE.md` 제외하고 새 폴더에 풀어 단일 커밋 저장소로 만든다. 원본 저장소는 읽기만 한다.
- verify: 스크래치 경로로 시험 실행 → 제외 대상 0개, 커밋 1개, 원본 저장소 무변경
- done: 인계 시점에 한 줄로 실행 가능
