<!--H1-->개 요

이 매뉴얼은 DataMeasurement 비전 검사 장비를 운용하는 현장 운영자를 위한 사용 설명서입니다.

DataMeasurement는 Top(위) / Side(옆) / Bottom(아래) 카메라로 제품을 촬영하고, 이미지 안에서 미리 정해 둔 위치까지의 거리를 측정하여 공차와 비교한 뒤 합격/불합격을 판정하는 장비입니다. 이 매뉴얼은 로그인 여부 확인부터 레시피(검사 품목) 불러오기, 검사 실행, 결과 확인까지 운영자가 매일 하는 조작을 순서대로 설명합니다.

측정 영역 그리기, 패턴 모델 생성, 기준좌표 티칭, 캘리브레이션, 계정 관리, 시스템 설정 변경처럼 화면 구성 자체를 바꾸는 작업은 이 매뉴얼에서 다루지 않습니다. 이런 작업은 반드시 교육을 받은 관리자 또는 엔지니어가 담당합니다.

본 장비는 장비 조작 교육을 이수한 운영자만 작동시켜야 합니다. 화면에 표시되는 절차를 정확히 따르지 않으면 잘못된 판정이 나올 수 있습니다.

장비 수리가 필요하거나 화면에 원인을 알 수 없는 오류가 반복되면 즉시 조작을 멈추고 관리자 또는 [연락처]로 연락하시기 바랍니다.

제품 사양 및 화면 구성은 소프트웨어 업데이트에 따라 예고 없이 바뀔 수 있습니다. 이 매뉴얼과 실제 화면이 다르면 실제 화면을 기준으로 삼고, 관리자에게 확인을 요청하십시오.

1. 시작하기 전에

## 1-1. 이 매뉴얼의 대상과 범위

- 현장에서 DataMeasurement 장비를 매일 조작하는 운영자를 대상으로 합니다.
- 다루는 범위: 로그인 여부 확인, 레시피(검사 품목) 불러오기, 검사 실행, 결과 확인, 조명/카메라 상태 확인, 문제 발생 시 1차 대응입니다.
- 다루지 않는 범위: 측정 영역(ROI) 그리기, 패턴 모델 생성, 기준좌표(Datum) 티칭, 캘리브레이션, 계정 관리, 시스템 설정 값 변경입니다. 이 작업들은 교육받은 관리자/엔지니어 전용입니다.

## 1-2. 장비가 하는 일

- DataMeasurement는 Top / Side / Bottom 카메라로 제품을 촬영하고, 촬영된 이미지에서 미리 정해 둔 위치(에지)까지의 거리를 측정합니다.
- 측정값을 정해진 공차(허용 범위)와 비교해서 합격/불합격을 판정합니다.
- 판정 결과는 화면에 바로 표시되고, 필요하면 엑셀 파일로 저장되거나 상위 장비(호스트)로 통신 전송됩니다.

## 1-3. 안전 및 취급 주의사항

- 본 장비는 장비 조작 교육을 받은 운영자만 사용해야 합니다.
- 카메라, 조명, 이동 축 등 하드웨어가 동작하는 중에는 장비 내부에 손을 넣지 않습니다.
- 화면에 낯선 오류 메시지가 반복해서 뜨면 임의로 여러 번 재시도하지 말고, 8장을 참고하거나 관리자에게 알립니다.
- 케이블 분리, 통신 포트 설정 변경, 소프트웨어 재설치 등은 운영자가 임의로 하지 않습니다.
- 자리를 비울 때는 로그인되어 있지 않은지 확인합니다. 로그인 상태로 두면 다른 사람이 실수로 설정을 바꿀 수 있습니다.

## 1-4. 운영자가 해도 되는 일 / 관리자에게 넘겨야 하는 일

운영자가 해도 되는 일입니다.

- 레시피 불러오기 (상단 메뉴 [RECIPE] 버튼 이용)
- 검사 실행 ([RUN] / [일괄검사]), 화면 확인용 촬영 ([Grab])
- 검사 결과 확인, 결과 리뷰어 / 통계분석 화면 열람
- 결과 화면 위 표시(overlay) 켜고 끄기
- 조명 채널이 켜져 있는지, 밝기가 정상인지 확인

관리자 / 엔지니어에게 넘겨야 하는 일입니다.

- 로그인이 필요한 화면 전체 (설정, 카메라 상세 속성, 조명 포트 설정, TCP 연결 상세)
- 측정 영역(ROI) 그리기 · 이동, 패턴 모델 생성, 기준좌표(Datum) 티칭, 캘리브레이션
- 레시피 삭제 · 복사, 공차 값 변경, 계정 추가 / 변경
- 중앙 화면 위쪽 도구모음 대부분은 이런 관리 작업 전용입니다. 로그인하지 않은 상태에서는 흐리게 표시되어 클릭할 수 없습니다. 흐리게 보이는 도구는 운영자가 사용하는 도구가 아니라는 뜻으로 이해하면 됩니다.

[그림 1-1] 장비 정면 외관
> 캡처 대상: 장비 전원이 켜진 정상 상태에서 정면 전체를 촬영. Top / Side / Bottom 카메라와 제어 PC 위치가 함께 보이도록.

2. 프로그램 시작과 화면 구성

## 2-1. 프로그램 실행과 초기화

- 바탕화면 아이콘 또는 시작 메뉴에서 프로그램을 실행합니다. 창 제목 표시줄에는 프로그램 이름이, 메뉴바에는 "Measurement Vision"이 표시됩니다.
- 실행 직후 카메라, 조명, 검사 시퀀스를 초기화하는 시간이 걸립니다. 이 동안 일부 버튼은 눌리지 않습니다.
- 초기화에 실패하면 오류 안내창이 뜹니다. 이 경우 8장을 참고하거나 관리자에게 알립니다.
- 프로그램은 마지막으로 사용하던 레시피를 자동으로 다시 불러옵니다. 레시피가 하나도 없던 경우에는 빈 화면으로 시작합니다.

[그림 2-1] 프로그램 실행 직후 초기화 화면
> 캡처 대상: 아이콘 더블클릭 직후, 초기화가 진행 중인 화면. 일부 버튼이 흐리게 보이는 상태.

## 2-2. 전체 화면 한눈에 보기

- 화면은 위에서부터 제목표시줄, 상단 메뉴바, 본문(좌측 검사항목 패널 + 중앙 이미지 · 결과 화면), 맨 아래 상태 표시줄 순서로 구성됩니다.
- 본문 영역 위쪽에는 탭이 있습니다. 기본으로 [검사] 탭이 선택되어 있으며, 이 매뉴얼은 [검사] 탭을 기준으로 설명합니다. 다른 탭은 별도의 정렬 비전 설비가 연결된 경우에만 쓰는 화면으로, 이 매뉴얼에서 다루지 않습니다.
- 좌측 패널과 중앙 화면 사이, 중앙 화면과 상태 표시줄 사이의 경계선을 마우스로 끌면 각 영역의 크기를 조절할 수 있습니다.

[그림 2-2] 초기화 완료 후 전체 화면 레이아웃
> 캡처 대상: 레시피가 로드된 상태의 전체 화면. 메뉴바, 좌측 패널, 중앙 화면, 상태 표시줄이 모두 보이게 촬영.

## 2-3. 상단 메뉴바 (OPERATION / CONTROL 그룹, 각 버튼의 역할)

- 왼쪽에는 회사 로고, 프로그램 이름, 현재 시퀀스 상태 표시가 있습니다. 상태 표시를 클릭하면 진행 상태 창이 열립니다.
- OPERATION 그룹: [LOGIN](로그인) / [RECIPE](레시피) / [SETTING](설정)
  - [SETTING]은 로그인해야 클릭할 수 있습니다. 로그인 전에는 흐리게 표시됩니다.
- CONTROL 그룹: [CAMERA](카메라) / [LIGHT](조명) / [CONNECT](연결) / 결과 리뷰어 / 통계분석
  - [CAMERA] / [LIGHT] / [CONNECT]는 로그인해야 클릭할 수 있습니다. 로그인 전에는 흐리게 표시됩니다.
  - 결과 리뷰어와 통계분석 버튼은 로그인 없이도 사용할 수 있습니다.
- 오른쪽에는 현재 날짜 · 시간과 프로그램 버전 정보가 표시됩니다.
- 버튼이 흐리게(반투명하게) 보이면 지금은 누를 수 없다는 뜻입니다. 대부분 로그인이 필요하다는 신호입니다.

[그림 2-3] 상단 메뉴바 확대
> 캡처 대상: 메뉴바 전체를 확대 촬영. 로그인 전 상태로, OPERATION / CONTROL 그룹 버튼과 흐리게 보이는 버튼이 함께 보이게.

## 2-4. 좌측 검사항목 패널

- 위쪽에 현재 레시피 이름과 "..." 버튼이 있습니다. "..." 버튼은 로그인해야 눌립니다.
- 그 아래 실행 버튼이 있습니다: [RUN](수동 검사) / [일괄검사] / [일괄Export]
- 실행 버튼 아래에는 검사 항목을 SHOT(촬영 위치)와 FAI(측정 항목), Datum(기준좌표) 계층으로 보여주는 나무 구조 목록이 있습니다. 항목을 체크(☐)하면 일괄검사 대상에 포함됩니다.
- 나무 구조 위쪽 도구모음에는 여러 버튼이 있습니다. 운영자가 쓰는 버튼은 [Grab](촬영), [검사Grab], [Load](이미지 불러오기), [Light](조명 미리보기) 정도이며, 나무 구조에서 항목을 선택해야 활성화됩니다. 나머지 버튼(SimFolder / Model / Copy / paste / Add / Del / Edit / Up / Down)은 레시피 구성을 바꾸는 관리자 전용 기능입니다.
- 맨 아래는 선택한 항목의 세부 속성을 보여주는 편집 영역입니다. 이 영역도 로그인해야 나타납니다.

[그림 2-4] 좌측 검사항목 패널 확대
> 캡처 대상: 레시피가 로드된 상태에서 좌측 패널 전체(레시피명, 실행 버튼, 나무 구조, 툴바)를 확대 촬영.

## 2-5. 중앙 화면(이미지 뷰어)과 결과 표

- 중앙 위쪽에는 그리기 도구모음이 있습니다. 이 도구들(사각형 / 다각형 / 원형 ROI, 기준좌표 티칭, 패턴 관련 버튼, 캘리브레이션 등)은 전부 관리자 전용 티칭 기능이므로 운영자는 사용하지 않습니다.
- 도구모음 중 운영자가 켜고 끌 수 있는 항목은 [측정 overlay] / [Datum 라인] / [패턴 ROI] 체크박스입니다. 결과 화면 위에 어떤 표시를 겹쳐 보여줄지 고르는 용도입니다.
- 이미지가 아직 없으면 화면 가운데에 "NO Image" 문구가 표시됩니다.
- 이미지 아래에는 측정 결과 표가 있습니다. 컬럼은 FAI / Measurement / Type / DatumRef / Nominal(기준값) / Tol+(공차 상한) / Tol-(공차 하한) / 측정값 / 판정입니다.
- 판정 결과에 따라 표의 각 행 색이 달라집니다: 합격은 초록 계열, 불합격은 붉은 계열, 아직 결과가 없으면 회색으로 표시됩니다.

[그림 2-5] 중앙 화면(이미지 뷰어)과 결과 표
> 캡처 대상: 검사를 1회 실행해 이미지와 결과 표가 함께 채워진 상태. 결과 표의 판정 컬럼과 행 색이 보이도록.

## 2-6. 상태 표시 영역 (시퀀스 상태, 날짜, 버전)

- 상단 메뉴바 오른쪽에 현재 시퀀스 상태(대기 / 실행 중 등)와 시퀀스 이름이 표시됩니다. 이 부분을 클릭하면 진행 상태를 보여주는 창이 열립니다.
- 화면 맨 아래 상태 표시줄에는 진행 메시지와 PC 자원 사용량(CPU / RAM / 디스크 사용률)이 표시됩니다. 평소에는 참고만 하면 됩니다. 사용률이 계속 매우 높게 유지되면 관리자에게 알립니다.

[그림 2-6] 하단 상태 표시줄 확대
> 캡처 대상: 화면 맨 아래 상태 표시줄 부분을 확대 촬영. 메시지 영역과 CPU / RAM / 디스크 사용률 막대가 보이도록.

3. 로그인

## 3-1. 로그인이 필요한 경우와 필요 없는 경우

- 이 장비에는 "운영자(Operator)"라는 별도 로그인 계정 등급이 없습니다. 계정 등급은 관리자(Admin)와 엔지니어(Engineer) 두 가지뿐입니다.
- 즉 현장 운영자는 평소에 **로그인하지 않은 상태**로 장비를 사용합니다. 로그인하지 않아도 레시피 불러오기(상단 메뉴 [RECIPE]), 검사 실행([RUN] / [일괄검사]), 결과 확인, 결과 리뷰어 / 통계분석 화면은 모두 사용할 수 있습니다.
- 로그인하지 않은 상태에서는 화면 좌측 상단 계정 표시 영역에 "OPERATOR"라는 문구가 보일 수 있습니다. 이것은 로그인 가능한 계정 등급이 아니라, "아직 로그인하지 않았다"는 기본 표시일 뿐입니다.
- 로그인은 [SETTING] / [CAMERA] / [LIGHT] / [CONNECT] 화면을 열거나, 레시피를 저장 · 삭제 · 복사하거나, 측정 영역을 편집하는 등 **관리 작업을 할 때만** 필요합니다. 이런 작업은 원칙적으로 관리자 또는 엔지니어가 담당합니다.

## 3-2. 로그인 화면 사용법

상단 메뉴바에서 [LOGIN] 버튼을 클릭하면 로그인 창이 열립니다.

① [LOGIN] 버튼을 클릭합니다.

② 로그인 창이 열립니다. 위쪽에 현재 로그인 상태가 표시됩니다. 로그인되어 있지 않으면 빨간 글씨로 "로그아웃됨"이라고 표시됩니다.

③ "사용자" 항목의 드롭다운에서 등록된 계정 ID를 선택합니다. 직접 입력하지 않고 목록에서 고릅니다.

④ "비밀번호" 입력란에 비밀번호를 입력합니다.

⑤ [로그인] 버튼을 클릭합니다.

⑥ 비밀번호가 맞으면 창이 닫히고 메뉴바에 계정 ID가 표시됩니다. 틀리면 "로그인 실패!"라는 제목과 "비밀번호가 일치하지 않습니다."라는 안내창이 뜨고, 비밀번호 입력란이 비워집니다.

계정 정보(ID / 비밀번호)는 운영자에게 배포하지 않습니다. 로그인이 필요한 작업이 생기면 관리자에게 요청하십시오.

[그림 3-1] 로그인 전 메뉴바 상태
> 캡처 대상: 로그인하지 않은 상태의 상단 메뉴바 왼쪽 부분. 계정 표시 영역과 흐리게 보이는 CAMERA / LIGHT / CONNECT / SETTING 버튼이 함께 보이도록. 실제 계정 문자열이 없는 화면이므로 그대로 촬영 가능.

[그림 3-2] 로그인 창
> 캡처 대상: [LOGIN] 버튼을 클릭해 로그인 창이 열린 직후. 사용자 드롭다운, 비밀번호 입력란, [로그인] / [로그아웃] 버튼이 모두 보이도록. 비밀번호는 입력하지 않은 빈 상태로 촬영.

## 3-3. 계정 등급별 사용 가능 범위

- 관리자(Admin) 또는 엔지니어(Engineer) 계정으로 로그인하면 [SETTING] / [CAMERA] / [LIGHT] / [CONNECT] 버튼과 좌측 패널의 레시피 편집("..." 버튼), 측정 영역 편집 도구가 모두 활성화됩니다.
- 레시피 삭제 · 복사처럼 일부 작업은 로그인 상태에서만 가능합니다. 로그인하지 않고 시도하면 "접근 거부됨"이라는 제목과 "admin 권한이 필요합니다."라는 안내창이 뜨고 작업이 취소됩니다.
- 계정을 추가 · 수정 · 삭제하는 화면은 로그인 창의 [편집] 버튼으로 열립니다. 이 버튼은 관리자 등급 계정으로 로그인했을 때만 눌립니다.

[그림 3-3] 로그인 성공 후 메뉴바 상태
> 캡처 대상: 로그인 성공 직후 상단 메뉴바. 계정 ID가 표시되고 CAMERA / LIGHT / CONNECT / SETTING 버튼이 진하게(활성) 보이는 상태.

## 3-4. 로그아웃

- 다시 [LOGIN] 버튼을 눌러 로그인 창을 열고 [로그아웃] 버튼을 클릭합니다.
- 로그아웃하면 관리 기능 버튼들이 다시 흐리게 바뀌며 클릭할 수 없게 됩니다.
- 자리를 비울 때는 반드시 로그아웃해서 다른 사람이 관리 기능을 실수로 건드리지 않게 합니다.

[그림 3-4] 로그아웃 직후 화면
> 캡처 대상: 로그아웃 버튼을 클릭한 직후의 메뉴바. 계정 표시가 다시 기본 상태로 바뀌고 관리 버튼들이 흐려진 모습.

4. 레시피(검사 품목) 다루기

## 4-1. 현재 레시피 확인

- 좌측 패널 위쪽에 현재 불러온 레시피 이름이 표시됩니다.
- 프로그램을 시작하면 마지막으로 쓰던 레시피가 자동으로 로드됩니다.
- 검사를 시작하기 전에 지금 생산 중인 제품과 화면에 표시된 레시피 이름이 맞는지 반드시 확인합니다.

## 4-2. 레시피 불러오기

운영자는 로그인 없이도 상단 메뉴바의 [RECIPE] 버튼으로 레시피를 불러올 수 있습니다.

① 상단 메뉴바에서 [RECIPE] 버튼을 클릭합니다.

② 레시피 목록 창이 열립니다. 왼쪽에 레시피 이름과 마지막 수정일이 나열됩니다.

③ 목록에서 불러올 레시피를 클릭합니다. 오른쪽에 썸네일 이미지와 설명 글이 표시됩니다.

④ [OK] 버튼을 클릭합니다.

⑤ 창이 닫히고 선택한 레시피가 로드됩니다. 실패하면 "레시피 로드에 실패하였습니다."라는 오류창이 뜹니다.

검사 시퀀스가 실행 중일 때는 레시피를 바꾸지 않습니다.

[그림 4-1] 상단 메뉴바 [RECIPE] 버튼
> 캡처 대상: 메뉴바에서 [RECIPE] 버튼 위치가 잘 보이도록 확대 촬영.

[그림 4-2] 레시피 목록 창
> 캡처 대상: [RECIPE] 버튼 클릭 직후 열린 레시피 창 전체. 좌측 목록(이름 / 수정일)과 우측 썸네일 · 설명 영역이 함께 보이도록.

[그림 4-3] 레시피 선택 후 OK 클릭 대기 상태
> 캡처 대상: 목록에서 레시피 하나를 클릭해 선택한 직후. [OK] 버튼이 활성화된 상태.

## 4-3. 레시피 저장 (Save)

- 레시피 저장 · 복사 · 삭제는 로그인한 상태에서만 할 수 있는 관리 작업입니다. 로그인 후 좌측 패널의 "..." 버튼을 누르면 [Save] / [Save As] / [Open Recipe] 메뉴가 나타납니다.
- 검사 시퀀스가 실행 중이면 저장되지 않고 "시스템이 Running 중입니다."라는 오류창이 뜹니다. 검사가 끝난 뒤 저장합니다.
- 레시피 안에 서로 엇갈리는 설정이 남아 있으면 "저장 불가" 안내와 함께 저장이 취소될 수 있습니다. 이 경우 레시피 구성을 바꾼 관리자에게 확인을 요청합니다.
- 운영자는 평소에 레시피 내용을 바꾸지 않으므로 저장 기능을 직접 쓸 일이 거의 없습니다. 레시피 값 변경이 필요하면 관리자에게 요청하십시오.

[그림 4-4] 로그인 후 좌측 패널의 "..." 버튼과 저장 메뉴
> 캡처 대상: 로그인한 상태에서 좌측 패널 "..." 버튼을 클릭해 [Save] / [Save As] / [Open Recipe] 메뉴가 펼쳐진 모습.

## 4-4. 다른 이름으로 저장 / 복사 (Save As)

- 레시피를 새 이름으로 복사할 때 사용합니다. 새 이름 입력 창이 뜨면 이름을 입력하고 확인합니다.
- 이미 있는 이름을 입력하면 이미 존재한다는 확인창이 뜨고, 계속 진행할지를 다시 묻습니다.
- 레시피 목록 창의 [COPY] / [Delete] 버튼도 같은 종류의 기능이며, 역시 로그인이 필요합니다.

[그림 4-5] 레시피 저장 / 복사 결과 안내창
> 캡처 대상: Save 또는 Save As 실행 후 뜨는 완료 또는 오류 안내창.

## 4-5. 레시피를 바꿀 때 주의할 점

- 레시피를 바꾸면 검사 항목(SHOT / FAI / Datum 구성)과 공차 값이 전부 바뀝니다. 지금 생산 중인 제품과 맞는 레시피인지 반드시 이름을 확인하고 불러옵니다.
- 레시피를 잘못 불러온 채로 검사를 진행하면 실제로는 불량인데 합격으로 나오거나 그 반대가 될 수 있습니다. 레시피 이름이 헷갈리면 관리자에게 확인을 요청하십시오.
- 레시피 이름과 실제 생산 품목이 다르면 절대 임의로 판단하지 말고, 검사를 시작하기 전에 확인부터 합니다.

5. 검사 실행

## 5-1. 수동 검사 (RUN)

① 좌측 나무 구조에서 검사할 시퀀스, SHOT, 또는 항목을 클릭해 선택합니다.

② 좌측 패널 위쪽의 [RUN] 버튼을 클릭합니다.

③ 같은 카메라를 쓰는 다른 시퀀스가 이미 동작 중이면 실행되지 않고 오류창이 뜹니다. 해당 시퀀스가 대기 상태가 될 때까지 기다립니다.

④ "OfflineInspectMode"(오프라인 검사 모드)가 켜져 있으면 확인창이 뜹니다. 메시지는 "실제 카메라로 촬영하지 않고 저장된 검사이미지로 검사합니다."이며, 지금 실물 제품을 촬영해 검사하려면 [Cancel]을 눌러 중단하고 관리자에게 설정을 확인받습니다. 저장 이미지로 계속 진행해도 되는 상황이면 [OK]를 클릭합니다.

⑤ 검사가 시작되면 상태 표시가 "실행 중"으로 바뀌고, 완료되면 이미지와 결과 표가 채워집니다.

오프라인 검사 모드가 켜진 줄 모르고 RUN 하면, 카메라 앞에 실제 부품이 있어도 과거에 저장된 이미지로 조용히 판정될 수 있습니다. ④ 단계의 확인창을 절대 무심코 넘기지 않습니다.

[그림 5-1] 트리에서 항목 선택 후 RUN 버튼
> 캡처 대상: 좌측 나무 구조에서 SHOT 또는 시퀀스 항목을 선택하고 [RUN] 버튼에 마우스를 올린 상태.

[그림 5-2] RUN 진행 중 화면
> 캡처 대상: [RUN] 클릭 직후, 상태 표시가 "실행 중"으로 바뀐 화면.

## 5-2. 화면 확인용 촬영 (Grab / 검사Grab)

- [Grab]: 지금 카메라로 한 장 찍어서 화면에 보여주기만 합니다. 측정은 하지 않습니다. 조명 상태나 제품이 카메라 시야에 잘 들어와 있는지 눈으로 확인할 때 사용합니다.
- [검사Grab]: 촬영한 이미지를 그 항목의 오프라인 검사용 이미지로 저장합니다. 이동 축이 없는 수동 지그에서 위치를 맞춘 뒤 기준 이미지를 만들 때 엔지니어가 사용하는 기능이며, 운영자는 보통 사용하지 않습니다.
- 두 버튼 모두 나무 구조에서 카메라를 쓰는 항목(SHOT, Datum 등)을 먼저 선택해야 활성화됩니다.
- [Light] 버튼을 누르면 선택한 항목에 설정된 조명이 지정된 밝기로 켜집니다. 촬영 전 조명 상태를 미리 볼 때 사용합니다.

[그림 5-3] Grab 버튼과 촬영 결과
> 캡처 대상: 항목 선택 후 [Grab] 버튼을 클릭해 화면에 이미지가 표시된 상태.

[그림 5-4] 검사Grab 실행 결과 확인
> 캡처 대상: [검사Grab] 클릭 후 저장 완료를 알 수 있는 화면(속성 편집 영역에 저장 경로가 갱신된 모습). 엔지니어 작업 예시로만 촬영.

## 5-3. 자동 운전 (상위 장비 연동 시 운영자가 볼 것)

- 실제 생산 라인에서는 상위 장비(호스트 / PLC)가 통신으로 검사 명령을 보내면 장비가 자동으로 촬영과 측정을 진행합니다. 이때 운영자가 직접 클릭할 것은 없습니다.
- 자동 운전 중에는 화면 상태 표시와 결과 표만 지켜보면 됩니다. 상태가 "실행 중"에서 오래 바뀌지 않거나 같은 오류가 반복되면 8장을 참고하거나 관리자에게 알립니다.
- 화면 중앙 아래쪽에 "수동 Z축 트리거"라고 표시된 임시 패널이 보일 수 있습니다. 이것은 이동 축 자동화가 아직 없는 구간을 위한 엔지니어용 임시 테스트 도구입니다. **운영자는 이 패널을 사용하지 않습니다.**

[그림 5-5] 자동 운전 중 상태 표시
> 캡처 대상: 상위 장비 연동으로 자동 검사가 진행 중일 때의 상태 표시줄과 결과 화면.

## 5-4. 일괄검사

여러 SHOT을 한 번에 연속으로 검사하고 결과를 모아 봅니다.

① 좌측 나무 구조에서 검사할 SHOT들의 체크박스(☐)를 체크합니다. 반드시 같은 시퀀스(Top끼리 또는 Bottom끼리)만 함께 선택합니다.

② [일괄검사] 버튼을 클릭합니다.

③ 체크한 SHOT이 없으면 "검사할 SHOT 을 체크하세요."라는 안내가 뜹니다. 서로 다른 시퀀스를 섞어 체크했으면 "한 시퀀스 내의 SHOT 만 함께 선택할 수 있습니다."라는 오류가 뜹니다.

④ 이미 다른 검사가 실행 중이면 "시퀀스가 이미 실행 중입니다."라는 오류가 뜨고 시작되지 않습니다.

⑤ 검사가 체크한 순서대로 진행되며, 완료되면 [일괄Export] 버튼이 활성화됩니다.

[그림 5-6] SHOT 체크 후 일괄검사 버튼
> 캡처 대상: 나무 구조에서 SHOT 여러 개를 체크한 상태와 활성화된 [일괄검사] 버튼.

## 5-5. 검사 중지와 재시작

- 검사 도중 비정상적으로 멈추면 상태 표시가 "오류"로 바뀌고 안내창이 뜰 수 있습니다. 내용을 확인하고 안내창을 닫은 뒤 다시 [RUN] 또는 [일괄검사]를 시도합니다.
- 같은 오류가 반복되면 화면을 캡처해 관리자에게 전달하고, 8장의 안내를 따릅니다.
- 프로그램을 종료할 때는 "정말로 프로그램을 종료하시겠습니까?"라는 확인창이 뜹니다. 검사가 진행 중이 아닌지 확인한 뒤 종료합니다.

6. 검사 결과 확인

## 6-1. 화면에서 합불(OK/NG) 확인하기

- 검사가 끝나면 중앙 화면 아래 결과 표의 행 색으로 합불을 바로 확인할 수 있습니다. 초록 계열 배경은 합격, 붉은 계열 배경은 불합격, 회색은 아직 결과가 없다는 뜻입니다.
- 판정 값은 OK(합격) / NG(불합격) / DETECT FAIL(측정 위치를 찾지 못함, 검출 실패) 세 가지로 표시됩니다.
- DETECT FAIL은 공차를 벗어난 것이 아니라 측정 자체가 되지 않은 경우입니다. 이 경우 조명, 제품 위치, 이물질 여부부터 확인합니다.

[그림 6-1] 합격(OK) 판정 화면
> 캡처 대상: 전 항목이 합격으로 판정된 결과 표. 행이 초록 계열로 표시된 상태.

[그림 6-2] 불합격(NG) 판정 화면
> 캡처 대상: 하나 이상 불합격이 포함된 결과 표. 붉은 계열 행이 보이는 상태(가능하면 실제 재현 사례, 없으면 과거 결과 화면으로 대체).

## 6-2. 측정 결과 표 읽는 법 (FAI / Measurement / Nominal / Tol+ / Tol- / 측정값 / 판정)

- FAI: 측정 항목 묶음의 이름입니다.
- Measurement: 그 안의 세부 측정 이름입니다.
- Type: 측정 종류입니다.
- DatumRef: 기준으로 삼은 좌표(Datum)의 이름입니다.
- Nominal: 기준값(설계값)입니다.
- Tol+ / Tol-: 기준값에서 허용되는 위쪽 / 아래쪽 공차입니다.
- 측정값: 실제로 측정된 값입니다.
- 판정: OK / NG / DETECT FAIL 입니다.
- 측정값이 "Nominal - Tol- ~ Nominal + Tol+" 범위 안에 있으면 합격입니다.

[그림 6-3] 측정 결과 표 확대
> 캡처 대상: 결과 표 컬럼 헤더(FAI / Measurement / Type / DatumRef / Nominal / Tol+ / Tol- / 측정값 / 판정)가 모두 잘 보이도록 확대 촬영.

## 6-3. 결과 이미지 위 표시 켜고 끄기 (측정 overlay / Datum 라인 / 패턴 ROI)

중앙 화면 위쪽의 체크박스로 이미지 위에 겹쳐 보이는 표시를 고를 수 있습니다.

- [측정 overlay]: 실제로 측정한 위치와 선을 이미지 위에 표시합니다.
- [Datum 라인]: 기준좌표로 쓴 선 / 점을 표시합니다.
- [패턴 ROI]: 위치 보정에 사용한 영역을 표시합니다.

판정 결과가 이상해 보일 때 이 표시들을 켜서 실제로 어느 위치를 측정했는지 눈으로 확인할 수 있습니다.

[그림 6-4] overlay 체크박스 조작 전후 비교
> 캡처 대상: [측정 overlay] 체크박스를 켰을 때와 껐을 때의 이미지 화면 두 가지(가능하면 한 화면에, 어렵다면 순서대로 2회 촬영).

## 6-4. 결과 리뷰어로 지난 결과 다시 보기

상단 메뉴바의 결과 리뷰어 버튼을 클릭하면 "결과 리뷰어"라는 별도 창이 열립니다.

① 좌측 [날짜 폴더 열기] 버튼으로 지난 결과가 저장된 날짜 폴더를 선택합니다.

② 왼쪽 목록에서 확인할 검사 회차를 클릭합니다.

③ 가운데에 그때 찍힌 이미지가, 오른쪽에 측정 결과 표가 표시됩니다. 표는 판정별로 행 색이 다릅니다: 불합격은 붉은 계열, 검출 실패는 주황 계열, 합격은 연두 계열입니다.

④ 오른쪽 위 "불량만 보기" 체크박스를 켜면 불합격 / 검출 실패 행만 걸러 볼 수 있습니다.

⑤ 결과 표에서 행을 클릭하면 그 측정 위치만 이미지에 강조되어 표시됩니다.

⑥ 확인이 끝나면 [엑셀 export] 버튼으로 선택한 회차를 엑셀 파일로 저장할 수 있습니다.

좌측의 "이미지 폴더 반복 검사" 기능은 반복 정밀도를 확인하는 엔지니어용 기능입니다. 운영자는 사용하지 않습니다.

[그림 6-5] 결과 리뷰어 창
> 캡처 대상: 결과 리뷰어 창 전체. 좌측 날짜 / 회차 목록, 가운데 이미지, 우측 측정 결과 표가 함께 보이도록.

## 6-5. 통계분석 화면

상단 메뉴바의 통계분석 버튼을 클릭하면 "양산 이력 통계 분석" 창이 열립니다.

① 위쪽에서 조회할 기간(시작일 ~ 종료일)과 레시피를 고릅니다.

② [조회] 버튼을 클릭합니다.

③ 가운데 표에 항목별 평균 / 표준편차 / 범위 / Cpk(공정능력) / 합격 수 / 불합격 수 / 검출 실패 수 / 수율이 나타납니다.

④ 표에서 항목을 클릭하면 아래쪽에 분포 히스토그램과 측정값 추이 그래프가 표시됩니다.

이 화면은 조회하고 확인만 하는 화면입니다. 값을 직접 입력하거나 바꾸는 곳이 아닙니다.

[그림 6-6] 통계분석 창
> 캡처 대상: 기간 / 레시피 조회 후 통계 표와 히스토그램 · 추이 그래프가 채워진 전체 창.

## 6-6. 일괄 Export 와 결과 파일이 저장되는 위치

- 일괄검사를 1회 이상 실행한 뒤 좌측 패널의 [일괄Export] 버튼을 클릭하면 파일 저장 창이 뜹니다. 아직 일괄검사 결과가 없으면 "먼저 일괄 검사를 실행하세요."라는 안내가 뜹니다.
- 기본 파일 이름은 "batch_저장시각.xlsx" 형식입니다.
- 저장이 끝나면 "저장 완료:" 라는 문구와 함께 저장 경로가 안내창에 표시됩니다. 실패하면 "export 실패 (로그 확인)"이라는 안내가 뜹니다.
- 결과 파일과 검사 이미지는 이 외에도 날짜별 폴더로 자동 저장됩니다. 기본 저장 위치는 관리자가 설정에서 바꿀 수 있으며, 기본값은 결과 저장 폴더(D:\Data\Result)입니다.
- 정확한 폴더는 결과 리뷰어의 [날짜 폴더 열기] 버튼을 눌렀을 때 뜨는 기본 경로로도 확인할 수 있습니다.

[그림 6-7] 일괄Export 저장 대화상자
> 캡처 대상: [일괄Export] 클릭 후 뜨는 파일 저장 대화상자(경로 · 파일명 입력 화면). 실제 사내 경로가 노출되지 않도록 필요하면 가리고 촬영.

7. 조명과 카메라 상태 확인

## 7-1. 카메라 연결 상태 확인 (CAMERA / CONNECT)

- [CAMERA] 버튼(로그인 필요)을 클릭하면 카메라 목록, 실시간 미리보기, 상세 속성 화면이 열립니다. 시퀀스가 실행 중이면 "시퀀스가 동작 중에 있습니다."라는 제목과 "윈도우를 표시할 수 없습니다. 모든 시퀀스 동작이 종료될 때까지 대기하여 주십시오."라는 안내창이 뜨고 열리지 않습니다.
- 운영자는 이 화면에서 카메라 상태 표시와 미리보기 영상이 정상으로 나오는지만 확인합니다. 노출 시간 같은 속성 값은 바꾸지 않습니다.
- [CONNECT] 버튼(로그인 필요)을 클릭하면 상위 장비(호스트 / PLC)와의 통신 상태 창이 열립니다. 연결된 장비 목록과 주고받은 메시지 로그가 표시됩니다.
- 이 창에는 통신 명령을 직접 보내는 테스트 버튼들이 있습니다. **운영자는 이 버튼들을 누르지 않습니다.** 실제 생산 중에 임의로 명령을 보내면 라인이 오작동할 수 있습니다. 연결 목록에 장비가 정상적으로 보이는지만 확인하고 창을 닫습니다.

[그림 7-1] CAMERA 창
> 캡처 대상: [CAMERA] 창이 열린 상태. 카메라 목록과 미리보기, 상태 표시가 보이도록.

[그림 7-2] CONNECT 창
> 캡처 대상: [CONNECT] 창이 열린 상태. 연결된 장비 목록과 메시지 로그가 보이도록. 테스트 버튼은 누르지 않은 상태로 촬영.

## 7-2. 조명 제어 창 사용법

- [LIGHT] 버튼(로그인 필요)을 클릭하면 조명 제어 창이 열립니다.
- 조명 그룹마다 켜짐 여부 체크박스와 밝기 슬라이더가 있습니다. 운영자는 이 체크박스와 슬라이더로 조명이 켜져 있는지, 밝기가 평소와 같은지 확인할 수 있습니다.
- 포트 번호, 통신 속도(Baudrate), [Open] / [Close] 연결 버튼은 조명 컨트롤러의 통신 설정입니다. **운영자는 이 부분을 건드리지 않습니다.** 잘못 바꾸면 조명 전체가 응답하지 않을 수 있습니다.
- 값을 확인한 뒤에는 [CANCEL] 버튼으로 창을 닫습니다. 아무 값도 바꾸지 않았다면 [OK]를 눌러도 되지만, 확실하지 않으면 [CANCEL]을 권장합니다.

[그림 7-3] 조명 제어 창
> 캡처 대상: [LIGHT] 창 전체. 조명 그룹별 체크박스와 밝기 슬라이더가 보이도록.

[그림 7-4] 조명 채널 체크박스 / 슬라이더 확대
> 캡처 대상: 조명 채널 하나의 체크박스(이름 포함)와 밝기 슬라이더를 확대 촬영.

## 7-3. 조명 / 카메라 이상이 의심될 때

- 화면에 이미지가 안 나오거나 너무 어둡게 / 밝게 나오면 먼저 [Grab]으로 다시 한 번 촬영해 봅니다.
- 같은 문제가 반복되면 [LIGHT] 창에서 해당 채널이 켜져 있는지, 밝기 값이 평소와 같은지 확인합니다.
- 조명 / 카메라 자체를 재설정해야 하는 경우(포트 재연결, 노출 값 변경 등)는 운영자가 직접 하지 말고 관리자에게 알립니다.

8. 문제가 생겼을 때

## 8-1. 화면에 이미지가 나오지 않을 때

- 중앙 화면에 "NO Image" 문구만 보이면 아직 촬영된 이미지가 없다는 뜻입니다. 나무 구조에서 항목을 선택하고 [Grab]으로 촬영해 봅니다.
- [Grab] 버튼이 흐리게 표시되어 눌리지 않으면, 나무 구조에서 카메라를 쓰는 항목(SHOT / Datum 등)을 먼저 선택합니다.
- 그래도 이미지가 안 나오면 [CAMERA] 창에서 카메라가 목록에 정상적으로 보이는지 확인합니다. 로그인이 필요하므로 관리자에게 요청합니다.

## 8-2. 계속 NG(불합격)가 날 때

- 결과 표에서 어느 측정 항목이 NG인지 확인합니다. 판정이 DETECT FAIL이면 공차 문제가 아니라 측정 위치를 못 찾은 것이므로, 조명 · 제품 위치 · 이물질 여부를 먼저 확인합니다.
- [측정 overlay] / [Datum 라인] 체크박스를 켜서 실제로 측정한 위치가 제품의 올바른 위치인지 눈으로 확인합니다.
- 같은 제품에서 항상 같은 항목이 NG로 나오면 레시피 문제일 수 있습니다. 임의로 공차 값을 바꾸지 말고 관리자에게 알립니다.

## 8-3. 오류 메시지가 떴을 때

- 오류 안내창은 빨간 테두리로 표시되며, 제목과 메시지, 상황에 따라 [예] / [아니오] / [취소] / [확인] 버튼이 나타납니다.
- 메시지 내용을 그대로 읽고, 화면을 캡처하거나 메모해 둡니다. 뜻을 모르는 오류는 임의로 여러 번 재시도하지 말고 관리자에게 전달합니다.
- [확인] / [예] 등으로 창을 닫은 뒤 같은 작업을 한 번만 다시 시도해 봅니다. 다시 같은 오류가 뜨면 더 반복하지 말고 8-5절에 따라 연락합니다.

[그림 8-1] 오류 메시지창 예시
> 캡처 대상: 실제로 발생한(또는 재현 가능한 가벼운) 오류 메시지창. 빨간 테두리와 상황에 맞는 버튼들이 보이도록.

## 8-4. 로그 파일 위치와 전달 방법

- 문제가 반복되면 관리자가 로그 파일을 확인해야 할 수 있습니다. 로그는 확장자 .log 파일로 날짜별로 쌓입니다.
- 기본 저장 위치입니다. 관리자가 설정에서 바꿀 수 있습니다.
  - 결과: D:\Data\Result
  - 검사 이미지: D:\Data\Image
  - 오류 로그: D:\Data\Error
  - 진행 로그(Trace): D:\Data\Trace
- 정확한 폴더는 결과 리뷰어의 [날짜 폴더 열기] 버튼을 눌렀을 때 뜨는 기본 경로로도 확인할 수 있습니다.
- 관리자에게 전달할 때는 문제가 발생한 날짜와 대략적인 시각, 어떤 레시피 · 항목이었는지를 함께 알려주면 확인이 빨라집니다.

[그림 8-2] 로그 / 결과 폴더 위치 확인
> 캡처 대상: 결과 리뷰어에서 [날짜 폴더 열기] 클릭 시 뜨는 폴더 선택 대화상자(기본 경로가 보이는 상태).

## 8-5. 관리자 / 제조사에 연락해야 하는 경우

- 같은 오류가 반복되거나, 원인을 알 수 없는 화면이 뜨거나, 하드웨어(카메라 · 조명 · 케이블)에 이상이 의심되면 즉시 조작을 멈추고 관리자에게 연락합니다.
- 관리자로도 해결되지 않으면 제조사 연락처([연락처])로 문의합니다.
- 연락할 때는 화면 캡처, 오류 메시지 전문, 발생 시각, 사용 중이던 레시피 이름을 함께 전달하면 확인이 빨라집니다.

[그림 8-3] 프로그램 종료 확인창
> 캡처 대상: 프로그램 종료(닫기 버튼) 시 뜨는 "정말로 프로그램을 종료하시겠습니까?" 확인창.

9. 티칭 (관리자 · 엔지니어 전용)

## 9-1. 티칭을 시작하기 전에

- 1-1절은 "측정 영역 그리기, 패턴 모델 생성, 기준좌표 티칭, 캘리브레이션 ... 은 이 매뉴얼에서 다루지 않습니다"라고 안내합니다. 이는 1~8장이 현장 운영자를 대상으로 하기 때문입니다. 이 장(9장)은 그 작업 중 Datum · 패턴(ModelFinder) · Align 티칭 세 가지를 관리자 · 엔지니어 대상으로 별도로 설명합니다.
- 티칭이란 제품이 놓이는 위치가 매번 조금씩 달라져도 장비가 같은 곳을 측정하도록, 화면에서 기준 위치를 직접 지정해 저장하는 작업입니다.
- 이 장의 작업을 시작하기 전에 로그인하십시오(로그인 방법은 3-2절 참고). 로그인하지 않으면 왼쪽 속성 편집 영역(파라미터 편집기)이 비활성화되어 값을 바꿀 수 없습니다. Datum · 패턴 티칭은 Admin · Engineer 등급 모두 가능하지만, 레시피 [COPY] · [Delete]는 3-3절과 같이 Admin 등급만 가능합니다.
- Align(Tray 비전 / Bottom 비전) 화면은 로그인 여부와 관계없이 조작할 수 있습니다. 그렇더라도 임의로 값을 바꾸면 검사 기준이 흐트러지므로 관리자 · 엔지니어만 다루도록 관리하십시오.
- 검사 시퀀스가 실행 중일 때 [검사Grab]을 누르면 "시퀀스가 검사 중입니다. Idle 상태에서 다시 시도하세요." 안내창이 뜨고 중단됩니다. [Grab]은 시퀀스 실행 중에는 화면 반응이 없을 수 있습니다. 상단 상태 표시가 "대기"일 때 티칭용 이미지를 확보하십시오.

**재티칭 전 레시피 폴더 전체 백업**

- 레시피는 파일 하나가 아니라 `D:\Data\Recipe\<레시피명>\` 폴더 전체입니다. 이 폴더 아래 시퀀스 · 항목별 하위 폴더에 모델 파일(`.shm` / `.ncm` / `.mmf`), 설정값(`.json`), 티칭 이미지가 함께 들어 있습니다.
- 재티칭하면 이 파일들이 같은 경로에 그대로 덮어써집니다. 되돌리려면 백업본이 반드시 있어야 합니다. 아래 두 방법 중 하나로 재티칭을 시작하기 전에 반드시 백업하십시오.

① [RECIPE] 버튼으로 레시피 목록 창을 엽니다(4-2절 참고).

② 백업할 레시피를 목록에서 선택하고 [COPY] 버튼을 클릭합니다. 로그인하지 않았거나 Admin 등급이 아니면 "접근 거부됨" / "admin 권한이 필요합니다." 안내창이 뜨고 중단됩니다.

③ 새 레시피 이름을 입력합니다. 원래 이름 뒤에 날짜를 붙이면 나중에 구분하기 쉽습니다(예: `FAI_1_260818_백업`). 같은 이름이 이미 있으면 덮어쓸지 확인하는 창이 뜹니다.

④ 폴더 전체가 새 이름으로 복제됩니다.

탐색기로 직접 복사해도 됩니다. 같은 레시피 목록 창의 [OPEN DIR] 버튼을 누르면 레시피 저장 폴더가 탐색기로 바로 열립니다. 거기서 백업할 레시피 폴더를 통째로 복사한 뒤 이름 뒤에 날짜를 붙여 보관하십시오.

[그림 9-1] 레시피 목록 창의 [COPY] 버튼
> 캡처 대상: [RECIPE]로 연 레시피 목록 창에서 백업할 레시피를 선택하고 [COPY] 버튼에 마우스를 올린 상태.

[그림 9-2] 새 레시피 이름 입력창
> 캡처 대상: [COPY] 클릭 후 뜨는 새 레시피 이름 입력창. 날짜를 붙인 백업용 이름을 입력한 상태.

[그림 9-3] 탐색기로 연 레시피 저장 폴더
> 캡처 대상: [OPEN DIR] 클릭 후 열린 탐색기 창. 레시피 폴더 목록이 보이도록.

## 9-2. Datum(기준좌표) 티칭

Datum은 제품 위치가 조금씩 달라져도 같은 기준으로 측정하기 위해 미리 찾아 두는 기준 좌표(선 / 점 / 원)입니다. 아래 절차로 새로 티칭하거나 기존 Datum을 다시 티칭할 수 있습니다.

왼쪽 속성 편집 영역에서 Datum 노드를 선택하면 `AlgorithmType` 항목이 보입니다. 이 값에 따라 그려야 하는 ROI 구성이 달라집니다.

| AlgorithmType 값 | 그려야 하는 ROI | 비고 |
|---|---|---|
| TwoLineIntersect | 직선 ROI 2개 | 기본값. 두 직선이 만나는 점이 기준 |
| CircleTwoHorizontal | 원 검색 ROI 1개 + 수평 ROI 2개 | 원 중심을 지나는 세로 가상선과 수평선의 교점 |
| VerticalTwoHorizontal | 수직 ROI 1개 + 수평 ROI 2개 | 수직선과 수평선의 교점 |
| VerticalTwoHorizontalDualImage | 수평 ROI 2개(가로축 이미지) + 수직 ROI 1개(세로축 이미지) | 이미지 2장을 따로 사용. TeachingImagePath / TeachingImagePath_Vertical 두 경로 모두 필요 |

절차(모든 알고리즘 공통 순서 — ROI 단계 수만 다릅니다):

① 왼쪽 나무 구조에서 티칭할 Datum 노드를 선택합니다. 속성 편집 영역에서 `AlgorithmType`이 원하는 값인지 먼저 확인합니다.

② 이미지를 확보합니다. 방법은 5-2절과 같습니다 — [Grab]으로 즉시 촬영하거나, VerticalTwoHorizontalDualImage라면 [Load]로 가로축 이미지를 먼저 불러와 `TeachingImagePath`를 채웁니다.

③ 중앙 화면 위 도구모음에서 [Teach Datum] 토글 버튼을 클릭합니다. Datum 노드를 선택하지 않았으면 "Datum 노드를 먼저 선택하세요." 안내창이 뜨고 중단됩니다.

④ 이미 티칭된 Datum이면 "이 Datum은 이미 티칭되어 있습니다. 기존 ROI로 재티칭하시겠습니까?" 확인창이 뜹니다. 기존 ROI를 그대로 쓰려면 [예]를 클릭합니다. ROI를 다시 그리려면, 먼저 왼쪽 속성 편집 영역에서 해당 단계의 Length1 / Length2(원이면 Radius) 값을 0으로 지운 뒤 다시 [Teach Datum]을 클릭합니다.

⑤ 화면 위쪽에 "Step 1/2: Line1 ROI를 드래그하세요"처럼 지금 그려야 할 단계가 안내됩니다. 안내대로 캔버스에서 마우스로 드래그해 ROI를 지정합니다. 알고리즘에 필요한 ROI를 전부 그릴 때까지 안내가 다음 단계로 이어집니다.

⑥ VerticalTwoHorizontalDualImage는 가로축(수평 ROI 2개) 단계가 끝나면 화면이 세로축 이미지로 자동 전환됩니다. `TeachingImagePath_Vertical`이 비어 있으면 "세로축 이미지를 Load 해주세요 (PropertyGrid의 TeachingImagePath_Vertical)"라는 주황색 안내가 뜨고 멈춥니다 — 속성 편집 영역에서 세로축 이미지 경로를 채운 뒤 다시 진행합니다.

⑦ 마지막 ROI를 그리면 자동으로 티칭이 실행됩니다. 성공하면 "Datum 티칭 완료 — Recipe Save 권장"이라는 초록 안내가 뜨고 화면에 검출 결과가 겹쳐 표시됩니다. 실패하면 "티칭 실패" 안내창에 원인이 함께 표시됩니다(예: 이미지가 없으면 "이미지가 없습니다. 먼저 Grab 또는 Load Image를 수행하세요.").

⑧ [Test Find] 버튼으로 결과를 확인합니다. 현재 이미지 또는 다른 파일로 다시 찾아보고, 찾은 위치가 실제 기준과 맞는지 화면에서 눈으로 확인합니다. 라인핏(2-직선 / CTH / VTH) 티칭이나 패턴 모델 생성 중 하나라도 완료돼야 [Test Find]를 쓸 수 있습니다. 못 찾으면 "Find 실패" 안내창에 원인이 표시됩니다.

⑨ 문제가 없으면 상단 메뉴바에서 레시피를 저장합니다(저장 방법은 4-3절 참고). 저장하지 않으면 프로그램을 껐다 켰을 때 티칭 결과가 사라집니다.

**참고: 마스터 이미지가 바뀌었을 때(Re-anchor)** — 기존 기준 이미지 자체가 다른 것으로 바뀌는 경우(예: 지그 교체), 이미 그려 둔 여러 측정 ROI를 하나씩 다시 그리는 대신 [Re-anchor] 버튼으로 한 번에 옮길 수 있습니다. 새 마스터 이미지를 Grab 또는 Load한 뒤 [Re-anchor]를 클릭하면 옛 Datum 기준으로 찾은 이동량만큼 관련 측정 ROI가 노란색 미리보기로 이동합니다. 미리보기가 실제 위치와 맞으면 [Apply]로 확정합니다(레시피가 자동으로 먼저 백업된 뒤 반영됩니다). 확정 후에는 이 Datum을 새 마스터로 다시 티칭하고 [Test Find]로 확인한 뒤 레시피를 저장해야 합니다. 미리보기가 맞지 않으면 [Cancel]로 취소합니다.

[그림 9-4] Datum 노드 선택과 AlgorithmType 확인
> 캡처 대상: 나무 구조에서 Datum 노드를 선택하고 속성 편집 영역에 AlgorithmType 드롭다운이 보이는 상태.

[그림 9-5] [Teach Datum] 클릭 직후 ROI 그리기 안내
> 캡처 대상: [Teach Datum] 클릭 후 화면 위에 "Step 1/○: ... ROI를 드래그하세요" 안내 문구가 뜬 상태.

[그림 9-6] ROI 드래그 중인 화면
> 캡처 대상: 캔버스에서 마우스로 ROI 사각형(또는 원)을 드래그하고 있는 도중 화면.

[그림 9-7] 티칭 완료 후 결과 오버레이
> 캡처 대상: 마지막 ROI를 그린 직후 "Datum 티칭 완료" 안내와 함께 검출 결과가 화면에 겹쳐 표시된 상태.

[그림 9-8] [Test Find] 결과 확인
> 캡처 대상: [Test Find] 클릭 후 검출 위치가 화면에 표시된 상태. 실제 기준 위치와 겹치는지 확인할 수 있도록.

## 9-3. 패턴(ModelFinder) 티칭

패턴 티칭은 제품의 특징적인 무늬(패턴)를 기준점으로 등록해 두는 작업입니다. 제품이 카메라 시야 안에서 x, y로 밀리거나 약간 돌아가 있어도, 이 패턴을 다시 찾아서 그 어긋난 만큼을 Datum · 측정 위치에 보정해 줍니다. Datum 노드 하나에 패턴을 최대 2개까지 등록할 수 있으며, 2개를 등록하면 회전(기울어짐) 보정 정밀도가 올라갑니다.

절차:

① 왼쪽 나무 구조에서 패턴을 등록할 Datum 노드를 선택합니다.

② 이미지를 확보합니다([Grab] 또는 [Load], 5-2절과 같은 버튼).

③ 중앙 화면 위 도구모음에서 [패턴 1] 버튼을 클릭합니다. "패턴 1 ROI를 새로 그리시겠습니까?" 확인창이 뜨면 [OK]를 클릭합니다(기존 패턴 1 영역이 있으면 새로 그린 영역으로 대체됩니다).

④ 화면 안내("패턴 ROI: 드래그하여 템플릿 영역을 지정하세요")에 따라 무늬가 뚜렷한 부분을 캔버스에서 드래그로 지정합니다. 지정을 마치면 "패턴 1 ROI 저장 완료" 초록 안내가 뜹니다.

⑤ [패턴 2] 버튼도 같은 방식으로 지정합니다. 패턴 1의 반대 대각 끝(가급적 멀리 떨어진 위치)에 그릴수록 회전 보정이 정밀해집니다.

⑥ [패턴 모델 생성] 버튼을 클릭합니다. 패턴 ROI를 그리지 않았으면 "패턴 ROI(Rect)를 먼저 그리세요. ([패턴 ROI] 버튼)" 안내창이 뜨고 중단됩니다. 패턴 2를 그리지 않았으면 "패턴 2를 그리지 않았습니다. 단일 패턴은 회전(tilt) 보정 정밀도가 낮습니다. 그래도 단일 패턴으로 모델을 생성하시겠습니까?" 확인창이 뜹니다 — 패턴 2 없이 진행하려면 [OK], 패턴 2를 마저 그리려면 [취소] 후 ⑤번으로 돌아갑니다.

⑦ 모델 생성에 성공하면 "모델 생성 완료" 창에 등급 기호(● 양호 / ▲ 주의 / ✕ 실패)와 점수가 함께 표시되고, "지금 Recipe Save 하시겠습니까?"라고 묻습니다. [예]를 클릭하면 패턴 모델 파일과 기준값이 레시피 폴더 안에 함께 저장됩니다. [아니오]를 클릭하면 "모델은 기록되었으나 저장하지 않았습니다. 종료 전 Recipe Save를 권장합니다." 안내가 뜨며, 이 경우 나중에 반드시 레시피를 저장해야 합니다.

⑧ 모델 파일(`.shm` 또는 `.ncm`)은 레시피 폴더 안 해당 시퀀스 · 항목 하위 경로에 저장됩니다. Datum 이름을 나중에 바꾸면 이 파일도 새 이름 경로로 자동으로 옮겨집니다.

⑨ 결과 확인은 9-2절 ⑧의 [Test Find]를 그대로 사용합니다. 패턴 정렬이 켜진 Datum은 [Test Find]가 패턴으로 찾은 위치까지 반영한 결과를 보여줍니다.

[그림 9-9] [패턴 1] ROI 지정
> 캡처 대상: [패턴 1] 클릭 후 확인창을 통과하고, 캔버스에서 무늬가 뚜렷한 영역을 드래그로 지정하는 화면.

[그림 9-10] [패턴 2] ROI 지정
> 캡처 대상: 패턴 1의 반대 대각 끝에 [패턴 2] ROI를 드래그로 지정하는 화면.

[그림 9-11] [패턴 모델 생성] 완료 안내창
> 캡처 대상: [패턴 모델 생성] 클릭 후 뜨는 "모델 생성 완료" 안내창. 점수와 Recipe Save 여부를 묻는 문구가 보이도록.

[그림 9-12] 패턴 ROI 오버레이 표시 상태
> 캡처 대상: [패턴 ROI] 오버레이 체크박스를 켠 상태에서 화면에 패턴 영역이 겹쳐 표시된 모습.

## 9-4. Align 티칭 — 화면 열기와 공통 절차 (Tray 기준)

Align은 별도의 정렬 비전 설비(이더넷 카메라)가 연결된 경우에만 쓰는 화면입니다(2-2절 참고). Datum · 패턴 티칭과 달리 [검사] 탭이 아니라 화면 위쪽의 다른 탭에서 이루어집니다.

- 화면 위쪽 탭에는 [검사] 외에 [Tray 비전] / [Bottom 비전] 탭이 있습니다. 이 PC에 설정된 이더넷 정렬 비전 모드에 따라 둘 중 하나만 나타납니다(둘 다 나타나지 않으면 이 기능이 꺼져 있는 것이므로 관리자에게 확인하십시오).
- 이 절에서는 두 화면의 공통 절차를 [Tray 비전] 탭 기준으로 설명합니다. Tray와 Bottom은 좌측 패널 구성이 거의 같습니다([Grab] / [Live] / [Stop] / [폴더 열기] / [◀ 이전] / [다음 ▶] / [ROI 1 그리기] / [ROI 2 그리기] / [티칭 저장] / [검사]). Bottom만의 차이는 9-5절에서 설명합니다.
- 이 화면은 [검사] 탭과 달리 로그인 여부와 관계없이 조작할 수 있습니다. 임의로 건드리면 정렬 기준이 바뀌므로 관리자 · 엔지니어만 다루십시오.

절차:

① 화면 위쪽 탭에서 [Tray 비전]을 클릭합니다.

② "카메라 / 이미지 로더" 영역에서 이미지를 확보합니다. [Grab]을 클릭하면 카메라로 한 장 촬영해 오른쪽 화면에 표시합니다(이 프로그램이 오프라인 / 시뮬레이션 구성으로 빌드된 경우 [Grab]은 카메라 대신 파일 선택 창을 엽니다). 이미 저장해 둔 이미지로 진행하려면 [폴더 열기]로 폴더를 지정한 뒤 [◀ 이전] / [다음 ▶]로 이미지를 넘깁니다.

③ "티칭 (ROI 2개)" 영역에서 [ROI 1 그리기]를 클릭합니다. 이미 ROI 1이 있으면 "ROI 1을(를) 삭제하고 다시 그리시겠습니까?" 확인창이 뜹니다. 캔버스에서 무늬가 뚜렷한 부분을 드래그로 지정합니다.

④ [ROI 2 그리기]를 클릭하고 같은 방식으로 두 번째 영역을 지정합니다.

⑤ [티칭 저장]을 클릭합니다. 이미지가 없으면 "이미지 없음 — Grab 먼저" 상태 문구가 뜨고 중단됩니다. 성공하면 티칭 상태 문구에 등급 기호(● 양호 / ▲ 주의 / ✕ 실패)와 점수가 함께 표시됩니다(예: "● 티칭 OK (HasTemplate=True, score 0.xxx)"). 실패하면 실패 사유가 같은 자리에 한국어로 표시됩니다.

⑥ [검사] 버튼으로 결과를 확인합니다. 티칭이 안 되어 있으면 "모델이 없습니다. 먼저 티칭을 완료하세요." 안내창이 뜨고 중단됩니다. 성공하면 오른쪽 화면에 보정 위치(주황 ROI 박스)와 검출 에지가 겹쳐 표시되고, 결과 문구에 오프셋 값이 표시됩니다. 못 찾으면 "검출 실패"로 표시됩니다.

⑦ [ROI 표시] / [에지 표시] 체크박스로 결과 오버레이를 켜고 끌 수 있습니다. 기본은 둘 다 켜짐입니다.

⑧ "동축 조명 (Align 전용)" 영역의 [동축 ON/OFF] 체크박스와 밝기 슬라이더로 이 화면 전용 동축 조명을 켜고 밝기를 조절할 수 있습니다. 값을 바꾸면 Grab · 티칭 · 검사 시점에 자동으로 같은 값이 적용되며, 화면을 나가도 값이 저장되어 다음에 열면 그대로 복원됩니다.

[그림 9-13] [Tray 비전] 탭 화면 전체
> 캡처 대상: 화면 위쪽에서 [Tray 비전] 탭을 클릭해 연 직후. 좌측 컨트롤 패널과 우측 뷰어가 모두 보이도록.

[그림 9-14] ROI 1 / ROI 2 지정 화면
> 캡처 대상: [ROI 1 그리기] 또는 [ROI 2 그리기] 클릭 후 캔버스에서 영역을 드래그로 지정하는 도중 화면.

[그림 9-15] [티칭 저장] 완료 후 상태 문구
> 캡처 대상: [티칭 저장] 클릭 후 좌측 패널에 등급 기호와 점수가 표시된 상태.

[그림 9-16] [검사] 결과 화면
> 캡처 대상: [검사] 클릭 후 우측 화면에 보정 ROI 박스와 검출 에지가 겹쳐 표시되고, 좌측에 결과 값이 표시된 상태.

[그림 9-17] 동축 조명 조절 영역
> 캡처 대상: "동축 조명 (Align 전용)" 영역에서 [동축 ON/OFF] 체크박스와 밝기 슬라이더가 보이도록 확대 촬영.

## 9-5. Align 티칭 — Bottom 화면의 차이점

[Bottom 비전] 탭은 9-4절 공통 절차와 같은 방식으로 작동하지만, 면 슬롯이 여러 개라는 점과 화면 아래쪽에 별도의 캘리브레이션 패널이 있다는 점이 다릅니다.

- "카메라 / 이미지 로더" 영역 위쪽에 "면 슬롯:" 드롭다운이 있습니다. `[3D] 3D_Top` / `[3D] 3D_Bottom` / `[2D] 2D_TOP` / `[2D] 2D_BOTTOM` / `[2D] 2D_SIDE_1` / `[2D] 2D_SIDE_2` 총 6개 슬롯 중 하나를 먼저 선택해야 합니다. 화면을 처음 열면 아무 슬롯도 선택돼 있지 않으며, 상태 문구에 "슬롯 선택 필요"가 표시됩니다.
- 슬롯을 선택하지 않고 [티칭 저장]을 클릭하면 "면 슬롯을 먼저 선택하세요"라는 안내만 뜨고 저장되지 않습니다. 반드시 슬롯을 먼저 고른 뒤 9-4절 ③~⑤ 순서(ROI 1 → ROI 2 → 티칭 저장)를 그 슬롯에 대해 수행합니다.
- ROI와 티칭 결과는 슬롯마다 따로 저장됩니다. 슬롯을 바꾸면 그 슬롯에 이미 저장된 ROI와 동축 조명 값이 자동으로 복원됩니다.
- 6개 슬롯을 전부 티칭해야 Bottom 검사가 온전히 동작합니다. 슬롯 하나를 빠뜨리면 그 슬롯만 검사 시 "모델이 없습니다" 상태로 남습니다.

**주의 — 화면 아래쪽 "피커센터 캘 (36-스텝)" 패널** — 이 패널([초기화] / [검색 ROI(원) 지정] / [Cal 모델 티칭] / [스텝 추가 (Grab+검출)] / [피커센터 계산] 버튼으로 구성)은 이 절에서 설명하는 Datum · 패턴 · Align 티칭과 **다른 별개의 작업**입니다. 피커(부품을 집는 장치)의 중심 좌표를 캘리브레이션하는 기능으로, 같은 화면 안에 있어 혼동하기 쉽지만 Align ROI 티칭과 순서나 목적이 다릅니다. 이 패널의 조작 절차는 이 매뉴얼이 다루는 범위 밖이므로, 담당 관리자 · 엔지니어에게 별도로 확인하십시오. [확인 필요: 피커센터 캘리브레이션 36-스텝의 정확한 조작 순서]

[그림 9-18] 면 슬롯 드롭다운
> 캡처 대상: "면 슬롯:" 드롭다운을 펼쳐 6개 슬롯 목록이 보이는 상태.

[그림 9-19] 슬롯 선택 후 상태 문구
> 캡처 대상: 슬롯 하나를 선택한 직후 "선택: ..." 상태 문구와 함께 그 슬롯의 티칭 상태가 표시된 화면.

[그림 9-20] 피커센터 캘 패널 (참고용)
> 캡처 대상: "피커센터 캘 (36-스텝)" 패널 전체. 5개 버튼과 누적 상태 문구가 보이도록. 버튼을 누르지 않은 상태로 촬영.

## 9-6. 티칭 후 확인과 자주 겪는 문제

- Datum · 패턴 · Align 세 가지 모두 티칭 직후 화면에는 즉시 반영되지만, 프로그램을 다시 켜면 레시피를 저장하지 않은 내용은 사라집니다. 세 가지 중 어느 것을 고쳤든 작업을 마치면 반드시 레시피를 저장하십시오(저장 방법은 4-3절 참고).
- Datum 노드의 이름(DatumName)을 바꾸면 그 Datum에 딸린 패턴 모델 파일도 새 이름 경로로 자동으로 옮겨집니다(9-3절 ⑧). 다만 이 자동 이동은 속성 편집 영역에서 사람이 직접 이름을 바꿀 때만 동작합니다.
- 티칭은 됐는데 검사에서 계속 실패할 때는 다음을 순서대로 확인하십시오.
  - 조명과 초점이 티칭할 때와 같은지 확인합니다. 화면에 뜨는 실패 안내 중에는 "조명과 초점이 티칭할 때와 같은지, 부품이 검색 범위 안에 들어와 있는지 확인하세요"처럼 원인을 직접 짚어 주는 문구가 있습니다. 안내 문구를 그대로 따릅니다.
  - [ROI 표시] / [에지 표시](Align) 또는 [측정 overlay] / [Datum 라인](Datum, 8-2절 참고) 체크박스를 켜서 실제로 찾은 위치가 제품의 올바른 위치와 겹치는지 눈으로 확인합니다.
  - 등급 기호가 ▲(주의)나 ✕(실패)로 표시되면 점수가 기준에 가깝거나 미달한 것입니다. ROI를 무늬가 더 뚜렷한 위치로 옮기거나 다시 티칭해 보십시오.
  - 그래도 반복해서 실패하면 임의로 여러 번 재시도하지 말고 8-5절에 따라 관리자 · 제조사에 연락하십시오.

[그림 9-21] 실패 원인 안내 문구 예시
> 캡처 대상: Datum 또는 Align 티칭 / 검사 실패 시 뜨는 안내창. 원인 설명 문구가 읽히도록.

[그림 9-22] 등급 기호가 표시된 티칭 상태 문구
> 캡처 대상: ● / ▲ / ✕ 등급 기호와 점수가 함께 표시된 티칭 상태 문구 부분을 확대 촬영.

부록 A. 용어 설명

- SHOT: 카메라가 한 번 찍는 촬영 위치입니다. 하나의 레시피 안에 여러 SHOT이 있을 수 있습니다.
- FAI: SHOT 안에서 측정하는 항목 묶음 하나입니다. 여러 개의 세부 측정(Measurement)을 포함할 수 있습니다.
- Datum: 측정의 기준이 되는 좌표(선 / 점 / 원)입니다. 제품이 놓인 위치가 조금씩 달라져도 이 기준을 먼저 찾아서 측정 위치를 맞춥니다.
- 공차(Tolerance): 기준값(Nominal)에서 허용되는 오차 범위입니다. Tol+(위쪽) / Tol-(아래쪽)로 나뉩니다.
- 판정(Judge): 측정값이 공차 범위 안인지 밖인지의 결과입니다. OK(합격) / NG(불합격) / DETECT FAIL(검출 실패)로 표시됩니다.
- 레시피(Recipe): 검사할 제품에 맞는 SHOT / FAI / Datum 구성과 공차 값을 모아 놓은 설정 묶음입니다.
- 일괄검사: 여러 SHOT을 체크해서 한 번에 순서대로 검사하는 기능입니다.
- overlay: 결과 이미지 위에 겹쳐서 보여주는 측정선 · 기준선 등의 표시입니다.
- 오프라인 검사 모드: 실제 카메라 촬영 대신 미리 저장해 둔 이미지로 검사하는 모드입니다. 지그 점검이나 재현 테스트에 사용합니다.

부록 B. 일상 점검 체크리스트

| 점검 항목 | 확인 방법 | 정상 기준 |
|---|---|---|
| 프로그램 실행 | 아이콘 실행 후 초기화 대기 | 오류창 없이 메인 화면이 표시됨 |
| 레시피 확인 | 좌측 패널 상단 레시피명 확인 | 생산 제품과 일치하는 레시피명이 표시됨 |
| 카메라 화면 | [Grab]으로 촬영 | 이미지가 선명하게 표시됨 |
| 조명 상태 | [LIGHT] 창에서 채널 확인 (관리자 동반 권장) | 필요한 채널이 켜져 있고 밝기가 평소와 같음 |
| 시퀀스 상태 | 상단 메뉴바 상태 표시 확인 | "대기" 상태이며 오류 · 멈춤이 없음 |
| 최근 결과 | 결과 리뷰어에서 최근 회차 확인 | 판정 결과가 정상적으로 기록되어 있음 |

이 체크리스트는 하루 작업을 시작하기 전에 5분 정도 훑어보는 용도입니다. 항목 중 하나라도 "정상 기준"을 벗어나면 곧바로 검사를 시작하지 말고 8장을 참고하거나 관리자에게 먼저 알립니다.
