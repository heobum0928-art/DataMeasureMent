# [비전→제어] $PREP 에 Type 필드 추가 요청

작성 2026-08-26 · 비전(허범기) · 대상: 제어팀

---

## 1. 요청 한 줄

`$PREP` 에 **Type(검사 대상) 필드를 추가**해 주십시오.

```
변경 전 :  $PREP:site,z_index@
변경 후 :  $PREP:site,Type,z_index@
```

`$TEST` 는 변경 없습니다(이미 Type 을 갖고 있음).

---

## 2. 왜 필요한가 — 조명 예열 대상이 특정되지 않습니다

### $PREP 의 역할

`$PREP` 은 단순한 "축 이동 알림"이 아닙니다.
비전은 `$PREP` 을 받으면 **그 촬영 위치에 맞는 조명을 미리 켜고 밝기를 세팅**합니다.
`$TEST` 가 올 때까지의 시간이 곧 **조명 안정화 시간**입니다.

이 예열이 필요한 이유는 조명이 완전히 안정되기 전에 촬영하면
**검출은 성공하지만 에지의 서브픽셀 위치가 미세하게 편향**되기 때문입니다.
공차 경계 근처의 항목에서 PASS/NG 가 조용히 흔들립니다.
알람도 없고 로그에도 안 남아 현장에서 원인 추적이 가장 어려운 유형입니다.
(비전 릴리스 1.5.x 에서 실제로 확인·수정된 결함 유형입니다.)

### 문제 — 조명 세팅은 "덮어쓰기"입니다

비전의 조명 적용은 채널을 하나씩 더하는 방식이 아니라,
**16개 채널 전체를 한 번에 절대값으로 설정**합니다.
해당 촬영이 쓰지 않는 채널은 명시적으로 OFF 로 만듭니다.

그런데 `$PREP` 에는 대상 정보가 없으므로, 비전은 **그 PC 에 등록된 모든 검사 대상에 대해
z_index 에 맞는 조명을 차례로 적용**합니다. 전부 덮어쓰기이므로 **마지막에 적용된 것만 남습니다.**

### 이건 이미 발생하고 있습니다 (SIDE 분리와 무관)

**PC1 은 CXP 보드가 1대뿐이라 TOP 과 BOTTOM 이 같은 카메라를 공유합니다.**
따라서 두 대상이 같은 PC 에 함께 등록되어 있고, 둘 다 z=0 을 씁니다.

```
$PREP z=0 수신
  → TOP    조명 적용 :  RING ON,  BACK OFF, ...
  → BOTTOM 조명 적용 :  BACK ON,  RING OFF, ...   ← 나중에 적용되어 살아남음
```

**TOP 을 검사할 차례여도 TOP 의 예열 조명이 지워집니다.**

지금 TOP 검사가 실패하지 않는 이유는, 비전이 촬영 직전에 자기 조명을 한 번 더
적용하기 때문입니다. 최종 촬영 조명 자체는 맞습니다.
**그러나 그렇게 되면 예열 시간이 0 이 되어 `$PREP` 이 아무 역할도 하지 못합니다.**
위에서 말한 "조용히 흔들리는" 조건이 그대로 성립합니다.

### SIDE 를 분리하면 같은 문제가 4배로 늘어납니다

제어팀 확정 스펙(2026-08-13)대로 **Type = 검사 대상**으로 바로잡기 위해
SIDE 를 지그 4개로 분리하고, **각 지그의 z_index 는 0 부터 시작**하도록 맞춥니다.

| Type | 대상 | z 범위 | 카메라 | 조명 |
|---|---|---|---|---|
| 0 | TOP | 0 | CXP 1대 (TOP/BOTTOM 공유) | RING |
| 1 | BOTTOM | 0 | CXP 1대 (TOP/BOTTOM 공유) | BACK |
| 2 | SIDE_1 (지그 3-1) | 0 ~ 4 | SIDE 1대 (4지그 공유) | BAR (4지그 공유) |
| 3 | SIDE_2 (지그 3-2) | 0 ~ 7 | SIDE 1대 (4지그 공유) | BAR (4지그 공유) |
| 4 | SIDE_3 (지그 4-2) | 0 ~ 9 | SIDE 1대 (4지그 공유) | BAR (4지그 공유) |
| 5 | SIDE_4 (지그 4-1) | 0 ~ 9 | SIDE 1대 (4지그 공유) | BAR (4지그 공유) |

SIDE 4개는 **같은 카메라에 더해 같은 조명 채널(BAR)까지 공유**합니다.
z 가 지그마다 0 부터 다시 시작하므로 네 지그가 전부 z=0,1,2… 를 갖게 되어,
`$PREP z=2` 하나에 **네 지그의 조명 설정이 연달아 덮어씌워집니다.**

### 정리

| | 현재 TOP/BOTTOM | 분리 후 SIDE_1~4 |
|---|---|---|
| 카메라 | 1대 공유 | 1대 공유 |
| 조명 채널 | 서로 다름 | **완전히 동일(BAR)** |
| $PREP 예열 | 마지막 대상만 유효 | 마지막 지그만 유효 |
| 결과 | 예열 시간 상실 | 예열 시간 상실 |

**근본 원인은 SIDE 분리가 아니라, "PC 한 대의 카메라 1대를 여러 검사 대상이 공유하는데
`$PREP` 에는 대상 정보가 없다"는 점입니다.** Type 을 추가하면 두 경우가 함께 해결됩니다.

## 3. 요청 포맷 상세

```
$PREP:site,Type,z_index@        →  $PREP_ACK:site,z_index,OK|NG@
$TEST:site,Type,자재번호@       →  $RESULT:site;Type;P|F|B;count@     (변경 없음)
```

- 필드 순서를 `site, Type, …` 로 둔 것은 **`$TEST` 와 동일하게 맞추기 위함**입니다.
- ⚠ **3번째 자리에 Type 을 넣지 말아 주십시오.** 현재 비전 파서는 구 펌웨어 호환을 위해
  `$PREP` 의 3번째 필드(옛 Op)를 읽지 않고 버립니다. 그 자리에 Type 을 넣으면 무시됩니다.

---

## 4. 동작 예시 — SIDE_2(Type 3) 한 지그 검사

```
→ $PREP:2,3,0@        기준점 1차 위치, 조명 ON
← $PREP_ACK:2,0,OK@
→ $PREP:2,3,1@        기준점 2차 위치
← $PREP_ACK:2,1,OK@
→ $PREP:2,3,2@        측정 1
← $PREP_ACK:2,2,OK@
→ $PREP:2,3,3@        측정 2 (SIDE_2 의 마지막 z)
← $PREP_ACK:2,3,OK@
→ $TEST:2,3,자재번호@
← $RESULT:2;3;P;2@    ← 이 지그의 최종 판정
```

---

## 5. 제어 쪽 이점

1. **지그별 개별 판정.** 지금은 z=15(전체 마지막)에서 P/F 가 한 번만 나와
   4개 중 어느 지그가 불량인지 알 수 없습니다. 분리 후에는 지그마다 P/F 가 나옵니다.
2. **택트 단축.** 1번 지그가 불량이어도 지금은 z=15 까지 11초를 다 씁니다.
   분리 후에는 해당 지그에서 바로 끝납니다.
3. **스펙과 구현 일치.** "Type = 검사 대상" 이 실제로 동작하게 됩니다.
   (현재 구현은 Type 값을 사실상 무시하고 z 로만 대상을 정하고 있습니다.)

---

## 6. 여유 z 안내

위 표의 z 범위는 현재 필요한 것보다 넓게 잡혀 있습니다.
(예: SIDE_3 는 지금 z=0~4 만 쓰지만 0~9 로 확보)

전체 40개 항목 구성을 목표로 앞으로 측정을 추가할 자리입니다.
**해당 z 로 `$PREP` 이 와도 비전은 정상 응답합니다**(검사 항목이 없는 위치로 처리).
제어 쪽에서 별도 처리는 불필요합니다.

---

## 7. 회신 요청

- [ ] `$PREP:site,Type,z_index@` 채택 가능 여부
- [ ] 적용 가능 시점
- [ ] (확인 요청) 현재 PC1 에서 TOP 검사와 BOTTOM 검사에 각각 `$PREP` 을 보내고 계신지

제어 변경이 어려우실 경우 비전 쪽 임시 대응안이 있으나,
**사이클 첫 `$PREP`(z=0)에서는 여전히 대상을 특정할 수 없어 완전한 해법이 아닙니다.**
가능하면 위 포맷 채택을 부탁드립니다.
